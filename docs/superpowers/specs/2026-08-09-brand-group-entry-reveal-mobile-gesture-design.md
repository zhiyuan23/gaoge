# Brand Group 单次入场与移动端手势优化设计

日期：2026-08-09

## 背景

首页与 Group 页已经使用持久路由壳层：上滑揭示的是真实 Group DOM，完成后只切换 URL 和页面布局模式。当前仍有两个体验问题：

1. Group 首屏导航、标题和组织结构在滑动阶段已经完整可见，进入后又受到页面状态变化影响，视觉上形成“先有、消失、再显示”的重复显现感。
2. 移动端拖动主要从底部 `44×44px` 入口按钮开始，提交距离使用桌面同款的视口高度 28%，快速甩动还要求约 `900px/s`，导致触发区域小、上滑不够灵敏。

本次不改变持久 DOM、路由隔离、视频加载策略和 Group 页面内容，只调整 Group 首屏的 staged/active 呈现状态，以及粗指针设备的手势捕获范围和意图阈值。

## 已确认方向

- 上滑期间先露出 Group 建筑背景，首屏导航、标题文案和产业组织结构保持隐藏。
- Group 到达视口并切换为 `/group` 后，首屏元素只执行一次“从无到有”的淡入上移，不再提前出现或二次闪烁。
- PC 与移动端采用同一套 Group 首屏揭示逻辑。
- 移动端可从首页非交互区域任意位置开始上滑，不再要求精确按住底部尖头。
- 移动端使用更低的距离与速度阈值，桌面端鼠标拖动和滚轮参数保持不变。
- 减少动态效果偏好下不执行整屏或首屏入场动画，内容直接进入最终状态。

## 目标

1. 从首页进入 Group 时，首屏元素只出现一次，过程中不存在“先显示—隐藏—再显示”。
2. Group 背景在整屏移动期间保持空间连续，用户始终知道目标页面来自首页下方。
3. 移动端从首页大部分非交互区域上滑都能产生即时、连续的 1:1 位移反馈。
4. 普通移动端上滑不需要超过约五分之一屏幕；短促但明确的甩动也能提交。
5. 导航链接、能力按钮、弹窗和其他交互区域保持原生点击行为，不被页面手势抢占。
6. 直达 `/group`、PC 滚轮、浏览器历史、首页视频隔离和无障碍行为不回归。

## 不在范围内

- 不改变 Group 页面业务内容、章节顺序、数据或背景素材。
- 不增加第三方手势或动画依赖。
- 不把 Group 内容重新拆成预览 DOM 与正式 DOM。
- 不新增向下滑动返回首页。
- 不改变桌面滚轮累计阈值与桌面甩动判断。
- 不让能力按钮、导航或弹窗内部手势触发页面切换。

## 方案比较

### 方案 A：背景随页滑入，首屏内容在激活后单次显现（采用）

Group 页面继续作为真实第二层移动。背景图和暗色环境始终随页面出现；导航、标题文案和产业组织结构在 staged 状态为透明，并在页面成为 active 后统一淡入上移。

优点是保留空间连续性，同时建立唯一、明确的内容入场时机。缺点是需要给 Group 首屏增加显式的展示状态，但状态边界清晰且不创建第二棵 DOM。

### 方案 B：Group 整页在完成后整体淡入

实现简单，但滑动过程中只能看到黑色或空白区域，失去“下一页就在下方”的空间提示，不采用。

### 方案 C：继续让内容随滑动出现，只移除可能的重复动画

改动最小，但不符合“进入 Group 直接从无到有”的确认方向，也无法形成明确的视觉节奏，不采用。

## Group 首屏展示状态

### 状态定义

`GroupPage` 增加明确的展示模式：

- `direct`：首次直接访问 `/group`。沿用 Group 自身的首屏入场动画。
- `staged`：Group 在首页下方预挂载。背景可见，首屏交互与内容保持透明。
- `active`：从首页完成进入并成为 `/group`。同一 DOM 上的首屏元素从 staged 状态执行一次淡入。

持久壳层根据会话来源和当前路径传递状态：

```text
直接 /group           -> direct
首页等待或滑动中      -> staged
首页完成并进入 /group -> active
浏览器返回首页        -> staged
```

状态变化不能更换 Group 根节点或首屏子节点的 key。

### 被控制的元素

只控制首个视口内会被用户观察到的前景元素：

- Group 顶部导航；
- `GAOGE GROUP`、主标题和说明文案；
- 产业组织结构、节点和连线。

建筑背景图、暗色渐变和 Group 页面底色在 staged 状态保持可见。首屏以下章节不增加统一入场动画，避免滚动页面出现大范围无意义淡入。

### 动画参数

- 初始：`opacity: 0; transform: translate3d(0, 8px, 0)`。
- 激活：`opacity: 1; transform: translate3d(0, 0, 0)`。
- 时长：导航与标题 `240ms`，组织结构 `280ms`。
- 曲线：`cubic-bezier(0.16, 1, 0.3, 1)`。
- 组织结构可比标题延后最多 `40ms`，不使用明显分段或逐卡片 stagger。
- 不使用 bounce，不在激活时重新播放整屏位移。

为了避免首次 CSS 应用造成闪现，staged 隐藏样式必须在 Group DOM 首次 commit 时已经存在，不能依赖挂载后的普通 `useEffect` 才添加。

### 与 Framer Motion 的关系

- `direct` 模式继续使用 `GroupHero` 现有入场动画。
- `staged` 与 `active` 模式继续向 `GroupHero` 传入 `skipEntranceAnimation`，避免 Framer Motion 与 CSS 首屏揭示同时控制 opacity/transform。
- 首页来源的单次显现由页面展示状态和 CSS 完成，不重新创建 Group 组件。

### 减少动态效果

在 `prefers-reduced-motion: reduce` 下：

- staged 状态仍保持首屏前景隐藏，防止提前出现；
- 切换为 active 时不做位移或渐变时长，直接显示最终状态；
- 直接 `/group` 沿用 `GroupHero` 当前的 reduced-motion 最终状态。

## 移动端手势

### 手势区域

粗指针设备且页面处于 home 模式时，`GroupSwipeEntry` 的首页视口成为纵向拖动捕获区域。底部尖头仍保留为点击入口和视觉提示，但不再是移动端唯一可拖动区域。

以下起点排除页面级手势：

- `a`；
- `button`（底部滑动入口按钮除外）；
- `dialog` 及其后代；
- 表单控件；
- `[data-group-transition-ignore]`。

底部入口按钮继续支持点击、键盘激活和从按钮本身开始的拖动。

### 浏览器触摸协商

首页手势场景在粗指针设备使用 `touch-action: pan-x`：保留系统横向手势协商，把纵向位移交给页面的 Pointer Events。组件使用 `setPointerCapture`，确保手指离开起点后仍连续跟随。

桌面精细指针不扩大拖动捕获范围，继续保留当前按钮拖动、顶部链接和滚轮行为。

### 移动端意图参数

粗指针设备采用独立参数：

- 开始跟随阈值：`8px`；
- 距离提交比例：视口高度的 `18%`；
- 快速甩动最小距离：视口高度的 `5%`；
- 最小向上速度：`650px/s`；
- 动量投影比例保持现有 `16%`；
- spring 继续继承手指释放速度；
- 有明确甩动速度时允许现有轻微 bounce，普通距离提交保持无 bounce。

桌面参数保持：`10px` 开始阈值、28% 距离提交、8% 快速甩动距离和 `900px/s` 最小速度。

### 输入所有权

- 同一时间只允许一个 pointer 控制页面。
- 手势开始后立即停止正在进行的回弹动画，并从当前 MotionValue 继续。
- 能力弹层打开、Group 未准备好、页面正在提交或已经进入 Group 时，继续沿用现有 guard。
- Group 未 ready 时最多显示克制的预揭示距离；模块 ready 后自动延续同一次进入意图。
- `pointercancel` 必须回弹且不吞掉下一次点击。

## 组件调整

### `HomeGroupRouteShell`

- 为首页来源的 Group 页面传入 `staged` 或 `active`。
- 直接 Group 分支传入 `direct` 或使用默认值。
- 不改变 Group 懒加载、direct-session 分支和视频隔离。

### `GroupPage`

- 用单一 `entryPresentation` 属性表达 `direct | staged | active`。
- 在 Group 根节点同步输出 `data-entry-presentation`，确保首次 commit 即具备正确样式。
- 首页来源的 staged/active 均跳过 `GroupHero` 自身动画；direct 保持现状。

### `BrandPageShell` / `GroupHero`

- 为 Group 顶部导航增加稳定的首屏揭示 class。
- 为 GroupHero 文案和产业结构增加两个稳定的揭示 class。
- 不把状态逻辑散落到产业节点或导航内部。

### `GroupSwipeEntry`

- 保留现有 MotionValue、spring、滚轮累计、回弹和准备队列。
- 新增粗指针判定与全视口 pointer 入口。
- 将距离与甩动阈值收敛到可测试的纯函数配置中。
- 精细指针仍只通过现有按钮拖动，不改变 PC 已确认的体验。

## 无障碍

- staged Group 层继续保持 `inert`、`aria-hidden` 和 `pointer-events: none`。
- 首屏前景透明期间不会进入 Tab 顺序，因为整个 Group 层已经 inert。
- active 后先移除 inert，再显示首屏内容；焦点不自动跳转。
- 底部尖头仍是语义完整的按钮，名称保持“上滑了解高歌集团”。
- 键盘 Enter/Space 继续触发进入，不要求执行拖动。

## 测试与验证

### 自动化测试

1. staged Group 根节点首次渲染即带 `data-entry-presentation="staged"`。
2. staged 导航、标题容器和产业结构使用统一揭示 class；背景不属于隐藏前景。
3. 从 staged 切换 active 时 Group 根节点和首屏内容节点引用保持不变。
4. active 状态只切换展示属性，不重新启用 `GroupHero` 的 Framer 初始动画。
5. direct `/group` 使用 `direct`，保留现有 Group 首屏入场。
6. 390×844 下，从首页普通非交互区域上滑 18% 以上可以提交。
7. 移动端约 5% 距离且速度超过 `650px/s` 可以提交；同距离慢拖回弹。
8. 桌面原有 28% 和 `900px/s` 判断保持不变。
9. 从链接、能力按钮、弹窗和表单控件开始的移动不会触发页面拖动。
10. 底部按钮点击、按钮拖动、滚轮累计、重复输入、加载失败、pointer cancel 和 reduced motion 测试继续通过。

### 浏览器检查

- 1440×900：点击、慢拖、快速甩动后，Group 背景连续，首屏元素只淡入一次。
- 390×844、320×800：从标题、图片空白区和页面下半部上滑都能跟手；从导航与能力按钮开始不会误触。
- 移动端普通上滑约 150px 能完成进入，短慢拖仍回弹。
- 逐帧观察 URL 更新前后，不出现首屏元素提前显示、清空或重复出现。
- reduced motion：完成后内容直接显示，无整屏或首屏位移动画。
- 直达 `/group`：无首页视频、poster 或 `SkiingPage` 请求。
- 控制台无 React、Pointer Events、passive listener 或资源警告。

## 成功标准

- 从首页进入 Group 时，导航、标题和产业组织结构由透明状态连续变为最终状态，只出现一次。
- 滑动阶段可见 Group 建筑背景，不出现黑屏或模拟预览。
- 390×844 上，从非交互内容区开始的约 18% 视口高度上滑稳定提交。
- 短而快速的移动端甩动可提交，同距离慢拖不误触。
- PC 已确认的按钮拖动、滚轮和转场节奏没有变化。
- Group DOM 连续性、直达性能隔离、历史返回、无障碍和减少动态效果继续满足上一版设计。
