# Desktop 首页与设置页设计

## 背景

当前 `apps/desktop` 已具备基础 Electron + React 桌面壳，但首页和设置页仍主要停留在演示态：

- 首页只有少量桥接示例与单一状态反馈
- 设置页仅支持输入一个主题标识字符串，并未真正驱动界面
- 桌面应用当前默认深色视觉，但不支持浅色 / 深色 / 跟随系统切换
- 桌面应用当前默认中文文案，但不支持中英文切换

本次目标是在不引入重型新依赖、且只改 `apps/desktop` 的前提下，把首页补齐为完整的可交互占位工作台，同时把设置页升级为真正可用的基础偏好页面，并让整个桌面应用兼容主题与语言切换。

## 目标

1. 首页升级为“指挥台混合版”占位工作台，而不是单一演示卡片。
2. 设置页支持基础桌面偏好设置：
   - 主题模式：`light` / `dark` / `system`
   - 语言：`zh-CN` / `en-US`
3. 主题切换能够作用于桌面壳、首页、设置页。
4. 语言切换能够覆盖基础界面文案：
   - 导航
   - 顶栏标题与搜索占位
   - 首页标题、按钮、卡片标题、表单标签
   - 设置页标题、选项文案、保存反馈
5. 所有偏好均通过现有本地设置能力持久化。

## 非目标

- 不引入完整第三方国际化框架
- 不扩展更多系统级设置（如开机启动、自动更新、启动页恢复等）
- 不改动 Electron 主进程架构与数据库结构
- 不把桌面端偏好层抽到 `packages/*`

## 用户确认的范围

- 首页方向：`指挥台混合版`
- 主题模式：`浅色 / 深色 / 跟随系统`
- 语言切换覆盖范围：`基础界面文案`

## 现状约束

- 状态管理当前仅有简单的 `zustand` UI store
- 本地设置已通过 `electronBridge.db.getSetting/setSetting` 接入 SQLite
- 全局样式当前写死在深色背景与深色文本语境
- 页面文案目前直接内嵌在组件中，未抽象成可切换词典

## 方案对比

### 方案 A：轻量本地化 + 本地偏好中心（推荐）

在 `apps/desktop` 内新增轻量偏好层：

- 一个统一的偏好 store 管理主题、语言与 hydration 状态
- 一个本地词典对象管理中英文基础文案
- 一套 CSS 变量承接 light/dark 视觉 token
- 现有页面只消费偏好层，不直接分散读写本地设置

优点：

- 改动集中，便于后续继续扩展页面
- 不引入重型依赖
- 能覆盖这次需求中的主题与语言联动

缺点：

- 需要补一层薄运行时结构
- 需要整理基础文案 key

### 方案 B：页面各自直接处理主题与语言

首页、设置页、壳层都直接分别读写本地设置和条件渲染。

优点：

- 起步快

缺点：

- 状态与持久化逻辑容易分散
- 后续新增页面时会重复实现
- 更容易遗漏壳层与页面的同步更新

### 方案 C：一次性引入完整 i18n / theme 基础设施

引入更完整的国际化与主题管理方案。

优点：

- 体系最完整

缺点：

- 对当前桌面端体量偏重
- 超出“基础能力补齐”的范围

本次采用 **方案 A**。

## 信息架构

### 桌面壳

桌面壳继续保留两页结构：

- 首页 `/`
- 设置页 `/settings`

但导航、顶栏、状态标签和搜索占位全部接入可切换文案与主题样式。

### 首页

首页调整为四个区域：

1. 欢迎区
   - 显示工作台名称
   - 显示当前语言与当前主题模式
   - 显示客户端版本
   - 保留桌面端定位说明
2. 快捷动作区
   - 打开官网
   - 保存工作台名称
   - 一个纯本地交互动作，如刷新今日摘要
3. 摘要与运营占位区
   - 3 个摘要卡片，如待确认球员、本周比赛、未完成事项
4. 双列交互区
   - 左侧：可勾选完成状态的近期事项列表
   - 右侧：可切换标签的阵容 / 比赛视图占位

页面底部或局部保留统一反馈文案，承接动作执行结果。

### 设置页

设置页调整为三个区域：

1. 主题设置区
   - 单选 `浅色 / 深色 / 跟随系统`
2. 语言设置区
   - 单选 `简体中文 / English`
3. 偏好状态区
   - 显示当前模式
   - 显示当前解析后的实际主题
   - 显示最近一次保存反馈

切换设置后应立即生效，并同步持久化到本地。

## 状态设计

新增桌面偏好 store，建议状态结构如下：

```ts
type ThemeMode = 'light' | 'dark' | 'system'
type Language = 'zh-CN' | 'en-US'
type ResolvedTheme = 'light' | 'dark'

interface PreferenceState {
  hydrated: boolean
  themeMode: ThemeMode
  language: Language
  resolvedTheme: ResolvedTheme
  hydrate(): Promise<void>
  setThemeMode(mode: ThemeMode): Promise<void>
  setLanguage(language: Language): Promise<void>
  syncSystemTheme(isDark: boolean): void
}
```

关键原则：

- `themeMode` 表示用户选择
- `resolvedTheme` 表示当前真正用于渲染的主题
- 当 `themeMode === 'system'` 时，`resolvedTheme` 由系统主题决定
- 应用启动时先 hydrate，再渲染最终偏好，尽量避免主题闪烁

## 主题方案

主题不通过大量条件 class 拼接实现，而是通过全局 `data-theme` + CSS 变量统一驱动。

### 主题模式

- `light`
- `dark`
- `system`

### 解析逻辑

- `light` => `resolvedTheme = 'light'`
- `dark` => `resolvedTheme = 'dark'`
- `system` => 读取 `window.matchMedia('(prefers-color-scheme: dark)')`

### 样式落点

在根节点设置：

```html
<html data-theme="light|dark"></html>
```

CSS 变量负责至少以下 token：

- app background
- panel background
- text primary / secondary
- border color
- accent color
- input background / button background

这样首页、设置页、壳层能统一响应主题变化。

## 文案与 i18n 方案

不引入第三方国际化库，采用轻量词典对象。

### 范围

接入基础界面文案：

- 导航 label / description
- 顶栏标题、搜索占位、状态标签
- 首页主标题、副标题、卡片标题、按钮文案、输入标签、反馈提示
- 设置页主标题、副标题、字段标题、选项文案、反馈提示

### 结构

建议维护：

```ts
const messages = {
  'zh-CN': { ... },
  'en-US': { ... },
}
```

并提供一个简单的 `t(key)` 访问方式，避免页面里直接写两套条件分支。

### 不在本轮覆盖的文案

- Electron 系统菜单文案动态切换
- 更深层业务模块文案

本轮仅保证 React 渲染层基础界面文案可切换。

## 交互设计

### 首页

- `打开官网`：
  - 调用现有 `electronBridge.shell.openExternal`
  - 根据结果更新反馈文案
- `保存工作台名称`：
  - 仍沿用现有本地设置 key 保存
  - 成功 / 失败都反馈
- `刷新今日摘要`：
  - 纯前端占位行为
  - 更新一组预设摘要数据或时间戳，证明首页具备交互状态
- `近期事项勾选`：
  - 本地 UI 状态切换，不要求持久化
- `阵容 / 比赛` 标签切换：
  - 本地 UI 状态切换，不要求持久化

### 设置页

- 用户点击主题模式：
  - 更新 store
  - 立即更新根主题
  - 持久化到本地设置
  - 更新状态反馈
- 用户点击语言：
  - 更新 store
  - 立即切换基础文案
  - 持久化到本地设置
  - 更新状态反馈
- 当主题模式为 `system`：
  - 页面说明中展示“跟随系统”
  - 另显示当前解析结果 `light` 或 `dark`

## 数据与持久化

继续复用现有本地设置能力，不新增新表。

建议使用以下 key：

- `home-demo-workspace`
- `desktop-theme-mode`
- `desktop-language`

约束：

- 页面不再直接散落读取 `theme`
- 统一由偏好 store 负责读取与写入

## 测试策略

坚持先补测试再补实现。

### HomePage

- 渲染完整占位首页
- 展示客户端版本与已保存工作台名称
- 点击官网按钮时调用 bridge 并更新反馈
- 点击保存工作台时调用持久化
- 点击刷新摘要会更新界面状态
- 点击事项勾选和标签切换会更新对应区域展示

### SettingsPage

- 读取已保存主题与语言
- 切换主题模式后更新页面状态并触发持久化
- 切换语言后基础文案发生变化
- 状态区能显示当前主题模式与解析后的主题

### App / AppShell

- 导航与顶栏文案能随语言切换
- 搜索占位能随语言切换
- 根节点主题标识随主题变化

## 实施步骤

1. 为首页、设置页、壳层新增或调整测试，先定义主题与语言切换行为。
2. 新增偏好 store 和轻量词典。
3. 在应用 providers 或壳层里完成偏好 hydration 与根主题同步。
4. 重构全局样式到 CSS 变量双主题模式。
5. 重构首页为完整占位工作台并补齐本地交互。
6. 重构设置页为真正可用的基础偏好页。
7. 跑 `apps/desktop` 相关测试，必要时再补 typecheck。

## 风险与控制

### 风险 1：首屏主题闪烁

控制方式：

- 在应用初始化时尽早 hydrate
- 默认值与当前深色视觉保持一致

### 风险 2：语言切换后测试文案脆弱

控制方式：

- 优先断言关键控件与明确文案
- 对重复出现的标题避免依赖脆弱计数

### 风险 3：主题样式改造影响现有视觉层级

控制方式：

- 用 CSS 变量替代硬编码颜色，而不是完全推翻现有布局结构
- 保持当前桌面端视觉方向，只扩展浅色主题适配

## 验收标准

满足以下条件即视为完成：

1. 首页呈现完整的混合型占位工作台，而不是单块演示内容。
2. 首页至少包含一个快捷动作、一个本地保存动作、一个摘要刷新动作、一个待办交互区、一个标签切换区。
3. 设置页支持 `浅色 / 深色 / 跟随系统` 三档主题模式。
4. 设置页支持 `简体中文 / English` 语言切换。
5. 切换主题时，桌面壳、首页、设置页样式同步更新。
6. 切换语言时，导航、标题、按钮、标签、搜索占位等基础文案同步更新。
7. 主题与语言设置可通过本地设置持久化，并在下次打开时恢复。
