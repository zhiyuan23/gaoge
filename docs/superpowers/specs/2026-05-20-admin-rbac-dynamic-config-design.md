# 后台 RBAC 动态配置设计

## 背景

当前 `feat/admin-rbac` 分支已经具备第一轮 RBAC 基础：

- `apps/api` 已有 `Role / Permission / Menu` 及关联表
- `用户管理` 已开始从单角色字段迁移到多角色绑定
- `角色管理` 已可维护角色并分配权限
- `菜单管理` 和 `权限管理` 已有真实页面骨架

但当前实现仍有两个关键不足：

- 权限管理主要依赖 `sync-builtins`，不能新增和删除自定义权限
- 菜单管理只是维护菜单表，缺少更严格的树结构校验和运行时边界说明

本次目标是在不重构整套 admin 路由系统的前提下，把菜单和权限改成主流 RBAC 中后台模式：菜单、权限、角色、用户都由数据库维护，页面组件仍由前端代码白名单提供。

## 目标

- 权限管理支持新增、编辑、启停、删除非内置权限
- 内置权限仍由系统同步，`code` 不可修改，内置权限不可删除
- 菜单管理支持数据化树表 CRUD、状态/显隐、访问权限绑定
- 菜单配置增加父子关系安全校验，避免循环树和错误父级
- 角色分配权限时使用更清晰的按模块/资源分组操作模式
- 用户权限运行时继续以角色聚合权限码为唯一授权来源

## 非目标

- 不做数据库任意指定 Vue 组件并动态创建页面
- 不做低代码页面渲染
- 不把菜单表作为唯一路由注册来源
- 不改变现有 `v-auth`、`meta.auth` 的权限码使用方式
- 不把小程序普通用户纳入后台 RBAC 角色分配

## 设计结论

采用“动态菜单权限 + 前端路由组件白名单”模式。

数据库负责：

- 菜单标题、图标、路径、排序、状态、显隐
- 菜单访问权限绑定
- 权限字典的内置同步与自定义维护
- 角色权限分配
- 用户角色分配

前端代码负责：

- 实际页面组件
- 静态路由模块和组件导入白名单
- 页面和按钮上使用的稳定权限码

这样能获得主流 RBAC 的可配置能力，同时避免把页面组件路径、懒加载映射和路由注册全部交给数据库配置造成运行时不可控。

## 权限管理

权限码格式使用三段式：

```text
module.resource.action
```

例如：

- `system.user.view`
- `system.role.assign-permission`
- `football.player.create`

新增自定义权限时：

- `code` 必填且唯一
- `code` 必须符合三段式格式
- `module/resource/action` 从 `code` 自动解析并保存
- `name`、`description`、`status` 由后台表单维护
- `isBuiltIn` 固定为 `false`

编辑权限时：

- 所有权限都可以编辑 `name / description / status`
- `code / module / resource / action / isBuiltIn` 不允许编辑

删除权限时：

- 内置权限不允许删除
- 已被角色绑定的权限不允许删除
- 已被菜单绑定的权限不允许删除

同步内置权限时：

- 只 upsert 内置定义
- 刷新内置权限元信息和内置绑定关系
- 不删除自定义权限

## 菜单管理

菜单类型保持两类：

- `catalog`：目录，只组织菜单层级
- `menu`：实际页面入口

菜单表维护：

- `parentId`
- `name`
- `title`
- `icon`
- `path`
- `routeName`
- `menuType`
- `sort`
- `status`
- `visible`
- `permissions`

约束：

- `routeName` 全局唯一
- 同父级下 `name` 唯一
- 同父级下 `path` 唯一
- 更新父级时不能选择自身或自身子孙
- 删除菜单前必须没有子菜单
- 内置菜单不允许删除

运行时边界：

- 菜单配置不直接创建新的 Vue 页面
- 如果一个菜单指向尚未存在的前端路由，它只是待接入配置，不应破坏当前路由注册
- 当前 admin 运行时仍以现有前端路由和 `meta.auth` 作为页面访问基础

## 页面操作模式

### 权限管理

- 顶部搜索：关键词、模块、状态
- 操作区：新增权限、同步内置权限
- 表格字段：权限名称、权限码、模块、资源、动作、说明、状态、内置、操作
- 行操作：编辑、启用/停用、删除
- 新增/编辑使用 `ElDialog destroy-on-close`

### 菜单管理

- 顶部搜索：关键词、类型、状态
- 操作区：新增根菜单
- 树表操作：新增子菜单、编辑、绑定权限、删除
- 权限绑定弹窗复用按模块/资源分组选择体验

### 角色管理

- 继续保留角色 CRUD
- 分配权限弹窗改为按模块/资源分组展示
- 支持快速查看已选数量

## 验证要求

- 后端服务测试覆盖权限新增、重复 code、非法 code、删除引用保护、内置删除保护
- 后端服务测试覆盖菜单循环父级保护
- 前端至少通过 typecheck，确保新增 API 类型和页面模型一致
- 保持现有用户管理和角色管理流程可用
