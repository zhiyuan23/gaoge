# 高歌内容运营矩阵页面重设计

## 背景

`apps/brand` 的 `/content` 已经展示高歌体育、高歌超级联赛、主理人个人 IP、平台覆盖与运营能力，但当前页面仍沿用早期内容矩阵方案：顶部导航没有持续的位置感，影像首屏与后续内容块的视觉语言不够统一，平台与运营能力也更接近标签和列表陈列。

本次重设计以已经完成的 `/digital` 为母品牌规范参考，而不是直接复制数字产品页面结构。两个页面承担不同职责：

- `/digital` 展示当前数字产品、未来产品规划与交付方式。
- `/content` 展示当前真实内容品牌或 IP、平台覆盖与运营闭环。

因此 `/content` 延续 `/digital` 的暗色材质、浮动胶囊导航、排版层级、圆角系统与克制动效，同时保留暖红强调色、真实影像与内容运营节奏。

## 设计判断

这是一次保留式重构，面向了解高歌内容业务、品牌与传播能力的访客。

- `DESIGN_VARIANCE: 7`：使用不对称首屏与 `1 + 2` 内容布局，但避免实验性滚动结构。
- `MOTION_INTENSITY: 5`：使用一次性章节进入、导航状态过渡与链接按压反馈，不使用循环动画。
- `VISUAL_DENSITY: 5`：信息完整但保持品牌页留白，不堆叠服务清单和运营数据。

继续使用当前 React、Tailwind CSS 与 Framer Motion 技术栈，不引入新的设计系统、组件库或动画依赖。

## 目标

- 让 `/content` 与 `/digital` 明显属于同一高歌母品牌体系。
- 让访问者快速理解高歌当前运营什么内容、覆盖哪些平台、如何形成完整运营链路。
- 保持高歌内容自己的暖红色、影像感与传播属性，不让页面变成数字产品页的换色版本。
- 只展示已经确认的内容品牌、IP、平台和能力，不虚构未来项目、账号链接或运营指标。
- 在桌面、平板和手机端保持导航单行、内容层级清晰且无横向页面溢出。

## 非目标

- 不增加“未来规划”模块。
- 不新增内容品牌、IP、栏目、账号链接、粉丝量、播放量或增长数据。
- 不接入 API、CMS、筛选、搜索、分页或内容详情页。
- 不修改 `/digital`、`/group`、首页或体育站点。
- 不把内容页改成面向客户销售内容服务的通用 agency 落地页。
- 不引入新的 UI、图标或动画依赖。

## 页面信息架构

页面按以下顺序组织：

1. 浮动品牌与章节导航
2. 内容主张首屏
3. 当前内容品牌与 IP
4. 平台矩阵
5. 运营闭环
6. 页脚

首屏回答“高歌内容关注什么”，当前内容回答“现在运营什么”，平台矩阵回答“内容在哪里发生”，运营闭环回答“内容如何持续运转”。

## 母品牌视觉继承

### 与 `/digital` 保持一致

- 使用同一浮动胶囊导航材质，包括深色半透明背景、背景模糊、内高光与柔和阴影。
- 大标题使用紧凑字距与短行高，正文使用舒适行距和低一级对比度。
- 内容容器沿用约 `24px` 的软圆角、低亮度细描边和同色系内阴影。
- 章节进入只使用透明度与小幅纵向位移，并提供减少动态效果降级。
- 可点击内容在 hover、focus-visible 与 pointer-down 时提供明确但克制的反馈。
- 透明材质提供减少透明度和增强对比度降级。

### 内容页自己的表达

- 保留低饱和暖红强调色，不切换为 `/digital` 的鼠尾草绿。
- 真实体育影像承担首屏与主要内容视觉，不绘制虚假平台页面或内容后台。
- 平台与运营流程使用传播路径和节奏变化表达，不复用产品路线图与交付能力布局。
- 页面整体保持单一暗色主题，不在中段切换为浅色杂志页面。

## 顶部导航

`BrandNavigation` 在 `/content` 下采用与 `/digital`、`/group` 相同的 sticky 浮动胶囊外观，并增加内容页私有章节导航：

- 桌面：概览、当前内容、平台矩阵、运营闭环
- 手机：概览、内容、平台、运营

导航要求：

- 保留 GAOGE 首页入口和当前“内容”区域标识。
- 使用 `IntersectionObserver` 更新当前章节。
- 当前项使用同体系短下划线指示器，并使用无弹跳 spring 在当前位置间移动。
- 点击章节使用稳定锚点；减少动态效果时使用即时跳转。
- 手机端四项整体右对齐，保持单行且不产生页面级横向滚动。

稳定章节 ID：

- `content-overview`
- `content-properties`
- `content-platforms`
- `content-loop`

内容页章节导航作为页面私有组件实现。数字页与内容页可以复用相同交互规律，但本次不提前抽象万能导航组件。

## 内容主张首屏

首屏采用与 `/digital` 对应的非对称两列结构：

- 左侧：`GAOGE CONTENT`、中文主张与一句辅助说明。
- 右侧：真实高歌体育影像，使用克制裁切与深色遮罩形成内容窗口。

主张保持：

> 让每一份热爱持续被看见。

辅助说明收敛为：

> 以内容与运营连接品牌、平台和真实社群。

首屏不增加 CTA、平台标签、运营步骤或数据。章节导航已经提供下行入口，避免在首屏重复导航意图。

首屏在常见桌面视口内完整呈现。移动端变为上下结构，先展示主张，再展示影像；使用动态视口单位或基于导航高度的最小高度，不使用固定 `100vh`。

## 当前内容品牌与 IP

当前内容模块展示现有三项运营对象：

1. 高歌体育：运营中，具有真实外部链接 `https://sports.gaoge.cc`。
2. 高歌超级联赛：建设中，不提供未确认链接。
3. 主理人个人 IP：建设中，不提供未确认链接。

布局采用不对称 `1 + 2`：

- 高歌体育占据主要区域，展示真实影像、名称、摘要、状态和平台覆盖。
- 高歌超级联赛与主理人个人 IP 使用两个更紧凑的次级内容面。
- 主要内容块与次级内容块使用不同构图，避免三张完全相同卡片。
- 只有存在 `href` 的内容块渲染为链接并显示外部跳转反馈。
- 无链接内容保持语义化只读，不使用箭头、上浮或其他伪点击暗示。

内容状态继续使用现有语义：运营中、建设中、规划中。本次不改变状态数据，也不把内容状态改成数字产品使用的“演示系统”。

## 平台矩阵

平台矩阵展示：

- 公众号
- 视频号
- 小红书
- 抖音
- B 站
- 社群与私域

平台不使用六张同尺寸卡片，也不继续表现为松散标签堆叠。采用一条具有传播路径感的横向覆盖面：

- 平台名称按内容触达顺序组织，但不声称固定业务流程。
- 使用一个完整容器、稀疏分隔与不同宽度的内容段形成节奏。
- 在桌面端保持横向阅读，在移动端变为两列或紧凑纵向分组。
- 不添加平台图标、账号名、粉丝数或未确认跳转地址。

## 运营闭环

运营闭环按现有能力组织为六个连续环节：

1. 内容策划
2. 图文与短视频生产
3. 多平台分发
4. 活动传播
5. 社群承接
6. 数据复盘

模块采用一条连续的运营路径，而不是六宫格功能卡：

- 桌面端使用横向分段结构，强调从策划到复盘后再次进入策划的循环关系。
- 移动端改为清晰的纵向步骤，不依赖横向拖拽。
- 不显示 `01 / 02` 等装饰性编号，不使用进度条或虚构完成度。
- 使用核心收束文案：`让内容持续发生，也持续被理解。`

## 页脚

继续使用 `BrandPageShell` 的正式品牌页页脚：

- 返回高歌首页
- 进入高歌数字

不增加版本号、地点、时间、社交账号或重复 CTA。

## 数据与组件边界

继续使用 `apps/brand/src/pages/content/data.ts` 作为内容页静态数据入口。现有 `ContentProperty` 模型足以支撑本次重构，不新增后端字段。

建议组件职责：

- `ContentPage.tsx`：页面编排、元数据与章节组合。
- `ContentSectionNavigation.tsx`：内容页章节观察、当前项与锚点交互。
- `ContentHero.tsx`：主张与真实影像。
- `CurrentContent.tsx`：当前品牌与 IP 的 `1 + 2` 展示。
- `ContentPlatforms.tsx`：平台覆盖面。
- `ContentOperatingLoop.tsx`：运营闭环。
- `ContentSectionReveal.tsx`：一次性章节进入与 reduced-motion 降级。

现有 `ContentPropertyBlock.tsx` 和 `PlatformRail.tsx` 可以在新结构不再需要时停止渲染，但不因本任务强制删除。内容页组件不得依赖数字页私有组件，集团页与数字页也不得反向依赖内容页。

`BrandNavigation` 仅扩展 `content` 的章节导航分支，不改变首页和其他概念页导航行为。

## 交互与动效

- 首屏文字与影像使用一次性、无弹跳 spring，响应约 `0.35-0.45s`。
- 章节进入使用透明度与小幅 `y` 位移，动效只表达层级与阅读顺序。
- 导航当前项使用 `bounce: 0` 的可重定向 spring。
- 高歌体育外链在 pointer-down 时立即缩放至约 `0.985`，释放后恢复。
- 不实现自动播放视频、拖拽、轮播、视差、滚动劫持或持续循环动画。
- 现有远程背景视频从首屏移除，避免加载、可用性和减少动态效果依赖。

## 响应式与可访问性

- 页面最小支持宽度为 320px，无页面级横向滚动。
- 首屏两列在小于 768px 时变为上下布局。
- 当前内容 `1 + 2` 在移动端变为单列，高歌体育保持最高视觉层级。
- 平台覆盖在移动端改为两列或紧凑纵向分组。
- 运营闭环在移动端改为纵向步骤，不要求横向拖动。
- 导航、高歌体育外链和页脚入口支持键盘访问与清晰焦点环。
- 不只依赖颜色表达状态，继续显示状态文字。
- `prefers-reduced-motion: reduce` 下取消位移和 spring，仅保留即时状态。
- `prefers-reduced-transparency: reduce` 下导航与内容表面使用近实色背景并移除模糊。
- `prefers-contrast: more` 下提高边框、辅助文字、状态与焦点环对比度。

## 测试与验证

自动化测试覆盖：

- `/content` 元数据保持正确。
- 页面展示高歌体育、高歌超级联赛和主理人个人 IP。
- 只有高歌体育提供真实外链，并保留新窗口安全属性。
- 内容状态文案保持运营中与建设中，不受数字页“演示系统”规则影响。
- 平台矩阵完整展示六个平台名称。
- 运营闭环完整展示六项现有能力。
- 章节导航链接到四个稳定 ID，并提供桌面与手机文案。
- 减少动态效果时章节与导航仍可正常使用。

```bash
pnpm --filter @gaoge/app-brand test

pnpm build:brand
pnpm exec eslint apps/brand/src

```

浏览器检查：

- 1440×900：首屏完整、导航单行、当前内容层级清晰。
- 1024×768：标题与影像比例合理，导航显示完整文案。
- 390×844：导航显示概览、内容、平台、运营并整体右对齐。
- 320×800：无页面级横向滚动，名称和状态不遮挡。
- 键盘：导航、高歌体育外链与页脚入口焦点顺序正确。
- 系统偏好：减少动态效果、减少透明度与增强对比度有明确降级。

## 成功标准

- 访问者无需完整阅读页面即可理解高歌当前运营对象、平台覆盖与运营闭环。
- `/content` 与 `/digital` 在导航、材质、排版、圆角与动效上属于同一母品牌体系。
- 暖红强调色、真实影像和运营路径使内容页保持独立辨识度。
- 页面不展示未来规划、虚构链接或虚构运营指标。
- 页面在 320px 以上无横向溢出，并支持键盘与系统偏好降级。
