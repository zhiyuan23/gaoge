# 新媒体项目命名设计

## 背景

当前仓库中的 `apps/web` 已承担官网职责。现在需要新增一个独立前台项目，主要承载新闻稿件，并为后续专题、人物、评论、影像等内容类型预留空间。

本次设计只解决命名问题，不进入信息架构、技术实现、数据模型或页面设计。

## 已确认前提

- 新项目是一个新应用，不复用 `apps/web` 作为同一站点内栏目
- 项目定位是“内容媒体站”，而不是“品牌新闻中心”
- 对外采用独立媒体品牌，不直接挂靠“高歌新闻”这一类命名
- 品牌气质偏数字媒体平台，而不是传统刊物或公告站
- 名称采用“中文品牌名 + 英文识别名”的双名结构
- 名称本身不显性包含“体育 / 球 / 比赛 / 赛场”等运动词
- 主要受众是中文用户，中文名优先，英文名主要服务识别、域名和社媒

## 命名目标

命名需要同时满足以下要求：

1. 能独立作为内容品牌成立，而不是官网下属栏目
2. 适配新闻、专题、人物、评论、影像等内容扩展
3. 不把品牌气质锁死在“公告”“政务新闻”或“传统杂志”方向
4. 工程命名与品牌命名解耦，避免 repo 目录和市场名称强绑定

## 命名结构

### 工程命名

- 应用目录名：`apps/media`
- 工作区包名：`@gaoge/app-media`

选择 `media` 而不是 `news`，是为了保留新闻稿件之外的内容扩展空间。`news` 会天然收窄为“新闻中心”，不利于后续承载专题、人物、评论、视频等内容。

### 品牌命名

- 中文品牌名：`在场`
- 英文识别名：`SCENE`
- 对外呈现：`在场 | SCENE`

## 方案对比

### 推荐方案：`在场 | SCENE`

推荐原因：

- “在场”天然带有现场、目击、参与、记录的语义，适合新闻稿件和媒体内容
- 不直接写体育，但与体育内容中的临场感、现场感是相容的
- 既能覆盖快讯，也能覆盖人物、专题、访谈、影像
- 品牌感足够清晰，不像“XX资讯”那样只是栏目名
- 英文 `SCENE` 易于做站点识别、社媒标识和后续栏目延展

### 备选方案：`余响 | ECHO`

特点：

- 更偏内容厂牌和表达气质
- 更适合评论、人物、播客、视频等深度内容
- 品牌感更强，但新闻即时性和现场感弱于“在场”

### 保留备选：`刻面 | FACET`

特点：

- 更现代、更冷静，数字媒体品牌感较强
- 适合栏目矩阵和编辑部化运作
- 差异化较强，但首屏理解成本高于“在场”

## 不建议采用的命名类型

- `XX新闻`、`XX资讯`
  - 会被理解为官网下属新闻栏目，不像独立媒体品牌
- 纯抽象数字产品名，如“脉冲”“流”“源”
  - 平台感有余，但媒体属性不够明确，前期教育成本高
- 显性体育刊物名，如“体育周刊”“看台”“场边”
  - 与“不显性带运动语义”的既定方向冲突

## 最终结论

本项目的命名结论如下：

- 工程命名：`apps/media`
- 工作区包名：`@gaoge/app-media`
- 对外品牌名：`在场`
- 英文识别名：`SCENE`
- 对外组合写法：`在场 | SCENE`
