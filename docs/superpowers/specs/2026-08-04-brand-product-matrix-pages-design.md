# 高歌品牌产品矩阵页面设计

## 背景

`apps/brand` 当前以 Skiing 概念页作为 `gaoge.cc` 的品牌首页，并通过首页导航表达“数字、内容、体育、未来”四个品牌方向。数字入口目前直接跳转 Gaoge Compass，内容入口仍是静态标签，无法完整展示高歌已经形成和正在规划的产品矩阵。

本次在 Brand 应用内新增两个正式二级页面：

- 高歌数字：展示高歌数字旗下的企业软件、消费者与体育产品、平台能力。
- 高歌内容：展示高歌运营的内容品牌、IP、多平台分发和运营能力。

两个页面用于品牌陈列，不承担产品后台、内容管理后台或完整产品中心的业务功能。

## 已确认方向

- 高歌数字页与高歌内容页都属于 Brand 站内正式页面，不属于 `/concepts/*` 实验页面。
- 页面路由分别为 `/digital` 和 `/content`。
- 两页采用“同一母品牌骨架，不同视觉气质”的设计方向。
- 高歌数字页展示完整产品矩阵，并严格区分运行中、建设中和规划中。
- 高歌内容页采用“真实内容品牌或 IP + 平台矩阵 + 运营能力”的混合结构。
- Brand 内部导航使用当前标签页；跳转独立产品站点时使用新标签页。
- “高歌内容”为暂定显示名称，但 `/content` 路由保持稳定。
- 第一版使用静态 TypeScript 数据，不接入 API、CMS、搜索或筛选。

## 目标

1. 让访问者从品牌首页进入高歌数字与高歌内容的完整矩阵，而不是只看到单一产品。
2. 明确区分真实运行、正在建设和长期规划，避免把规划能力写成已交付成果。
3. 让两个页面属于同一高歌母品牌，同时分别表达数字产品的系统感和内容运营的生命力。
4. 建立可持续增加产品、内容品牌、平台和外部链接的数据结构。
5. 保持 `/concepts/*` 作为独立的视觉方案开发入口，不让正式内容页混入概念注册表。

## 非目标

- 不建设通用 CMS、产品管理后台或远程数据接口。
- 不加入搜索、筛选、排序和分页。
- 不为规划中产品创建空链接或伪造演示页面。
- 不虚构客户数量、用户量、粉丝量、播放量和增长数据。
- 不修改高歌体育独立站点的页面或路由。
- 不把实验概念组件提前抽入共享包。

## 路由与导航

Brand 应用路由调整为：

```text
/                 高歌品牌首页
/digital          高歌数字产品矩阵
/content          高歌内容运营矩阵
/concepts         品牌视觉方案索引
/concepts/*       独立概念页面
```

首页导航规则：

| 入口     | 目标                      | 打开方式                   |
| -------- | ------------------------- | -------------------------- |
| 高歌标识 | `/`                       | 当前标签页                 |
| 数字     | `/digital`                | 当前标签页                 |
| 内容     | `/content`                | 当前标签页                 |
| 体育     | `https://sports.gaoge.cc` | 新标签页                   |
| 未来     | 无                        | 不可点击，显示领域拓展状态 |

首页三个品牌角标同时成为语义明确的入口：

- `DIGITAL / 数字产品` 进入 `/digital`。
- `CONTENT / 内容创造` 进入 `/content`。
- `SPORTS / 体育热爱` 打开 `https://sports.gaoge.cc`。

这样可以在移动端中央导航隐藏时继续提供数字、内容和体育入口。角标必须支持键盘焦点和清晰的悬停或按压反馈，但不得变成高对比度按钮。

产品矩阵页顶部沿用同一母品牌导航，并明确标识当前领域。两个矩阵页都提供返回高歌首页的可见入口，页尾提供数字与内容之间的交叉入口。

## 应用内目录与职责

正式品牌页面与实验概念分开：

```text
apps/brand/src/
├── brand/
│   ├── components/
│   │   ├── BrandNavigation.tsx
│   │   ├── BrandPageShell.tsx
│   │   ├── MatrixStatus.tsx
│   │   └── MediaWithFallback.tsx
│   └── metadata.ts
├── pages/
│   ├── digital/
│   │   ├── DigitalPage.tsx
│   │   ├── data.ts
│   │   └── components/
│   └── content/
│       ├── ContentPage.tsx
│       ├── config.ts
│       ├── data.ts
│       └── components/
└── concepts/
    └── ...
```

共享边界保持克制：

- `BrandNavigation` 统一正式品牌导航、当前领域状态和内外部链接行为。
- `BrandPageShell` 只负责正式品牌页的页面级背景、导航和页尾骨架。
- `MatrixStatus` 统一状态值、显示文案和可访问名称。
- `MediaWithFallback` 处理真实图片加载失败时的品牌化文字兜底。
- 数字产品卡和内容影像块分别保留在自己的页面目录，不抽象成同一种万能卡片。
- Skiing 首页改用正式的 `BrandNavigation`，其他概念页保持独立。

## 静态数据模型

### 通用状态

```ts
type MatrixStatus = 'live' | 'building' | 'planned'
```

数字页对应文案：

- `live`：运行中
- `building`：建设中
- `planned`：规划中

内容页对应文案：

- `live`：运营中
- `building`：建设中
- `planned`：规划中

### 数字产品

```ts
interface DigitalProduct {
  readonly category: 'enterprise' | 'consumer' | 'platform'
  readonly englishName?: string
  readonly featured: boolean
  readonly href?: string
  readonly name: string
  readonly status: MatrixStatus
  readonly summary: string
  readonly tags: readonly string[]
  readonly visual?: {
    readonly alt: string
    readonly src: string
  }
}
```

只有存在真实目标地址的产品才提供 `href`。外部链接统一使用 `_blank`、`noopener` 和 `noreferrer`。

### 内容品牌与 IP

```ts
type ContentPlatform = 'wechat' | 'channels' | 'xiaohongshu' | 'douyin' | 'bilibili' | 'community'

interface ContentProperty {
  readonly href?: string
  readonly name: string
  readonly platforms: readonly ContentPlatform[]
  readonly status: MatrixStatus
  readonly summary: string
  readonly type: 'brand' | 'ip'
  readonly visual?: {
    readonly alt: string
    readonly src: string
  }
}
```

平台名称和“高歌内容”暂定品牌名集中配置，不散落在页面组件内。

## 高歌数字页面

### 定位

英文标识：

> GAOGE DIGITAL

中文主张：

> 让复杂业务有清晰系统。

页面语气应理性、明确、可信，强调产品边界、运行状态和多端交付能力。

### 内容层级

1. 品牌首屏
   - GAOGE DIGITAL
   - 中文定位
   - 企业软件、消费者应用与平台能力的简短说明
2. 重点产品
   - Gaoge Compass / 高歌跨境 ERP，运行中，链接 `https://compass.gaoge.cc`
   - Gaoge Club / 高歌 Club，建设中
   - 高歌客户 CRM，建设中
3. 产品矩阵
   - 企业软件：高歌通用 ERP、高歌内容 CMS、高歌协同 OA、高歌洞察 BI
   - 消费者与体育产品：赛事活动、会员、票券和后续高歌系应用
   - 平台能力：高歌 IAM、工作流、数据、AI、连接器和多端交付
4. 品牌能力说明
   - 独立产品
   - 共享平台能力
   - 独立部署、专属云与后续 SaaS
5. 页尾
   - 返回高歌首页
   - 进入高歌内容

知识库将 Gaoge Compass 定义为高歌跨境电商 ERP 系统，将高歌通用 ERP 视为后续独立产品，并要求产品之间保持独立后端、数据库和部署边界。页面文案不得把它们描述为同一系统的不同模块。

### 布局

- 首屏使用大字号品牌标识和简短定位，不堆叠功能清单。
- 重点产品使用不对称 `1 + 2` 布局，Compass 占据主要视觉区域。
- 规划产品使用紧凑产品目录或横向产品带，不使用六张完全相同的功能卡。
- 有真实界面的产品优先使用真实产品截图。
- 没有真实素材时使用名称、品牌色和状态形成的文字视觉面，不绘制虚假后台界面。

### 视觉

- 主色为冷白、银灰、石墨和低饱和冷色。
- 保持与首页一致的全圆角交互系统和高对比度排版。
- 网格更清晰，留白更理性，避免科技蓝霓虹和通用 SaaS 渐变。

## 高歌内容页面

### 定位

暂定英文标识：

> GAOGE CONTENT

中文主张：

> 让每一份热爱持续被看见。

页面不把内容运营描述为孤立的发帖服务，而是展示真实品牌或 IP、内容生产、多平台分发、社群承接和复盘形成的运营闭环。

### 内容层级

1. 品牌首屏
   - GAOGE CONTENT
   - 中文定位
   - 品牌 IP、多平台内容和社群运营的简短说明
2. 运营对象
   - 高歌体育
   - 高歌超级联赛
   - 主理人个人 IP
   - 后续新增的独立内容品牌
3. 平台矩阵
   - 公众号
   - 视频号
   - 小红书
   - 抖音
   - B 站
   - 社群与私域
4. 运营能力
   - 内容策划
   - 图文与短视频生产
   - 多平台分发
   - 活动传播
   - 社群承接
   - 数据复盘
5. 页尾
   - 返回高歌首页
   - 进入高歌数字

首版只有高歌体育使用已确认的外部地址 `https://sports.gaoge.cc`。高歌超级联赛、个人 IP 和各平台账号在获得准确公开地址前不提供外部链接。

### 布局

- 首屏保持品牌宣言感，但比数字页更强调影像。
- 高歌体育、高歌超级联赛和个人 IP 使用大小不同的影像块组成内容矩阵。
- 平台覆盖使用简洁标签，不表现为一组同尺寸产品卡。
- 运营能力通过短文案与真实内容案例组合呈现，不建立普通六宫格功能区。
- 页面可持续增加内容品牌、平台和代表作品，不改变主骨架。

### 视觉

- 延续母品牌暗色基底，加入克制的暖红、肤色和影像色彩。
- 使用杂志式排版、裁切影像和不对称节奏。
- 不使用虚构的粉丝增长图表、平台数据面板或装饰性统计数字。

## 媒体资源策略

- 优先使用现有产品真实截图、运营海报、赛事照片和已公开内容素材。
- 所有图片必须有与内容一致的 `alt` 文本。
- 图片必须预留尺寸，避免布局偏移。
- 图片加载失败时显示产品或内容品牌名称、状态和品牌色文字面。
- 不把外部产品页面伪造成手写的后台截图。
- 远程素材地址必须集中在数据文件中，便于后续替换。

## 页面元信息

每个正式页面独立设置标题与描述：

- `/digital`
  - 标题：`高歌数字 - 数字产品矩阵`
  - 描述：`高歌数字旗下企业软件、消费者应用与平台能力。`
- `/content`
  - 标题：`高歌内容 - 内容运营矩阵`
  - 描述：`高歌旗下内容品牌、IP、多平台运营与社群能力。`

页面卸载后不能把标题错误地遗留给其他路由。元信息逻辑收敛为 Brand 内部可复用能力。

## 交互与可访问性

- 所有站内导航使用 React Router。
- 所有外部链接使用新标签页，并包含安全属性。
- 规划中条目渲染为非交互内容，不使用禁用链接模拟按钮。
- 当前导航领域使用视觉状态和 `aria-current="page"`。
- 首页角标变成链接后保留原有视觉构图，并增加焦点状态。
- 图片错误兜底不能丢失产品或内容名称。
- 所有文字和状态在视频或图片背景上满足可读性要求。
- 移动端不依赖隐藏的中央导航完成主要路径。
- 动效遵循 `prefers-reduced-motion`，不使用滚动监听驱动 React 高频更新。

## 错误与空状态

第一版没有远程数据请求，因此不设计网络加载与接口错误状态。

需要处理的静态异常包括：

- 页面配置为空时显示明确的矩阵暂无内容提示，而不是空白页面。
- 视觉素材缺失或加载失败时使用品牌化文字兜底。
- 产品缺少外部链接时保持为普通内容，不渲染点击行为。
- 路由加载继续使用 Brand 当前的懒加载占位。
- 未匹配路由保持当前返回品牌首页的行为。

## 测试与验证

### 自动化测试

- `/digital` 与 `/content` 可直接访问。
- 首页导航中的数字与内容使用站内路由。
- 体育继续使用外部新标签页。
- 首页三个角标具备正确目标。
- 数字页展示重点产品、产品分类和状态。
- 内容页展示运营对象、平台矩阵和运营能力。
- 当前导航具有 `aria-current="page"`。
- 有链接的外部条目包含 `_blank`、`noopener` 和 `noreferrer`。
- 规划中条目不是链接。
- 页面标题随路由正确变化。
- `/concepts/*` 现有注册与旧路径重定向不回归。

### 浏览器验证

检查 `/`、`/digital` 和 `/content`：

- 桌面端正常宽度
- 390px 移动端
- 减少动态效果偏好
- 无水平溢出
- 无内容遮挡
- 无浏览器控制台警告或错误
- 站内与外部链接行为符合约定

## 成功标准

- 访问者能从首页进入高歌数字与高歌内容，不需要知道产品的独立域名。
- 高歌数字页能区分重点产品、完整产品矩阵和规划状态。
- 高歌内容页能同时表达真实运营对象、多平台覆盖和运营闭环。
- 两页具有一致的母品牌导航和信息逻辑，但视觉表现不重复。
- 所有外部链接、状态和产品边界真实、可验证且不产生过度承诺。
- 新页面在桌面端、移动端和减少动态效果环境中可完整访问。
