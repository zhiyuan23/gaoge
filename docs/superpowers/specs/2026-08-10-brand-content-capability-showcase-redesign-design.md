# 高歌内容能力展示页重设计

## 背景

`apps/brand` 的 `/content` 当前采用“内容运营矩阵”定位，主要展示高歌体育、高歌超级联赛、主理人个人 IP、平台覆盖和运营闭环。其中高歌体育提供真实外链，各内容对象还显示“运营中”“建设中”等状态。

这种结构与 `/digital` 的产品矩阵表达过于接近，容易让访问者把 `/content` 理解为另一组可进入、可运行的高歌产品或内容账号。实际定位应当不同：

- `/digital` 展示高歌已经运行或规划中的数字产品，并允许进入真实产品。
- `/content` 展示高歌围绕内容创作、全平台运营和真实社群连接形成的综合能力。

本次将 `/content` 从“内容项目与平台目录”重设计为“品牌感受 + 能力证明”的内容能力展示页。

## 已确认方向

页面同时面向普通品牌访客和潜在合作方：

- 先通过高歌的内容主张和真实影像建立品牌感受。
- 再通过核心能力、真实实践、内容形态、全平台运营与工作方法证明高歌具备完整内容能力。
- 不采用纯氛围品牌叙事，避免能力过于抽象。
- 不采用传统广告公司式服务清单，避免页面模板化和销售感过强。

页面正文不承担产品、站点或社交账号导航职责。

## 目标

- 让访问者明确理解高歌内容是一组能力，而不是一组可运行产品。
- 保留高歌内容的品牌主张、真实感、体育现场感与社群属性。
- 清晰展示从策略、创作、现场表达，到全平台运营、互动承接和数据复盘的完整能力。
- 使用高歌体育、高歌超级联赛和主理人内容实践作为能力证据，而不是产品入口。
- 与 `/digital` 保持同一母品牌的排版、材质和导航体系，同时形成明显不同的叙事结构。
- 只展示已经确认的实践、平台和能力，不虚构内容、账号、链接或运营数据。

## 非目标

- 不接入 API、CMS、搜索、筛选、分页或内容详情页。
- 不新增内容项目、平台账号、粉丝量、播放量、增长率或合作客户。
- 不把 `/content` 改造成报价、留资或销售转化页面。
- 不调整 `/digital`、`/group`、首页、体育站点或其他 Concepts 页面。
- 不修改路由、权限、数据模型、部署方式或跨应用依赖。
- 不引入新的 UI、图标、动画或数据可视化依赖。

## 页面叙事

页面回答八个连续问题：

1. 高歌内容相信什么？
2. 高歌如何理解内容？
3. 高歌具备哪些核心能力？
4. 这些能力从哪里形成？
5. 高歌可以使用哪些内容形态？
6. 高歌如何进行全平台运营？
7. 内容如何持续运转？
8. 内容最终为品牌留下什么？

最终阅读顺序为：

```text
品牌主张
→ 内容理念
→ 核心能力
→ 真实实践
→ 内容形态
→ 全平台运营
→ 工作方法
→ 长期价值
```

这套顺序先建立认同，再展示能力与证据，最后收束到长期价值。

## 页面内容

### 1. 品牌主张

首屏保留已确认文案：

> GAOGE CONTENT
>
> 让每一份热爱<br />
> 持续被看见。
>
> 以内容与运营连接品牌、平台和真实社群。

首屏只建立品牌定位和情绪，不增加 CTA、平台标签、产品状态、运营数据或内容入口。

视觉使用真实人物、赛事或社群现场影像，不使用产品界面、平台后台截图或虚构内容卡片。

### 2. 内容理念

标题：

> 内容不是一次传播，<br />
> 而是持续建立关系。

展示三项内容观：

#### 发现真实故事

从人物、赛事、品牌和社群中，找到值得长期表达的内容。

#### 建立长期表达

形成稳定的主题、语言、视觉与内容节奏。

#### 连接真实社群

让内容进入讨论、参与和关系沉淀，而不只获得一次曝光。

本章节负责说明高歌内容的核心判断，避免页面直接从服务项目开始。

### 3. 核心能力

标题：

> 从内容发生，<br />
> 到关系留下。

展示四个能力领域：

#### 内容策略

品牌内容定位、主题规划、栏目体系与传播节奏。

#### 内容创作

人物采访、赛事记录、图文策划、短视频与专题内容。

#### 现场表达

赛事和活动现场记录、即时内容生产与氛围塑造。

#### 运营连接

平台运营、内容发布、互动维护、社群承接与持续复盘。

能力内容应说明“解决什么问题”，不扩写为未经验证的服务范围、团队规模或交付承诺。

### 4. 真实实践

标题：

> 能力来自<br />
> 持续实践。

展示三个实践对象：

#### 高歌体育

围绕体育文化，持续记录赛事、人物与真实现场。

能力证明：品牌内容体系、多形态创作、持续运营。

#### 高歌超级联赛

从赛事发生到传播扩散，建立完整的内容现场。

能力证明：赛事叙事、活动传播、社群连接。

#### 主理人内容实践

将产品、体育和长期实践转化为个人化表达。

能力证明：个人 IP 定位、观点表达、长期栏目。

这三个对象统一作为静态实践案例展示：

- 不显示“运营中”“建设中”“规划中”等产品状态。
- 不提供正文链接、外部跳转箭头或伪点击反馈。
- 不显示平台标签、账号名或账号入口。
- 不暗示三个对象具有相同成熟度或商业规模。

### 5. 内容形态

标题：

> 让不同的故事，<br />
> 找到适合的表达。

展示高歌能够承载的内容类型：

- 人物故事
- 赛事记录
- 品牌专题
- 图文内容
- 短视频
- 活动现场
- 社群内容
- 长期栏目

本章节以真实影像和编辑化排版形成内容墙，不使用八张同构服务卡。内容墙不伪造文章标题、封面来源、发布日期、播放量或其他内容数据。

### 6. 全平台运营

标题：

> 一套内容策略，<br />
> 进入每一个适合的场域。

说明文案：

> 不是把同一份内容机械复制到所有平台，而是保持统一的内容核心，再依据平台语境调整表达形态、发布节奏与互动方式。

平台覆盖展示：

| 平台       | 运营侧重点           |
| ---------- | -------------------- |
| 公众号     | 深度内容与品牌沉淀   |
| 视频号     | 即时触达与社交传播   |
| 小红书     | 场景表达与兴趣发现   |
| 抖音       | 短视频叙事与广泛触达 |
| B 站       | 中长内容与兴趣沉淀   |
| 社群与私域 | 互动承接与长期关系   |

同时展示五项全平台运营能力：

#### 统一主题规划

保持品牌主张、内容主题和阶段目标一致。

#### 平台原生适配

根据用户习惯调整标题、比例、节奏和内容结构。

#### 协同发布运营

建立发布节奏，让不同平台共同完成传播目标。

#### 互动与社群承接

回应讨论，把平台触达转化为持续关系。

#### 数据观察复盘

理解内容反馈，持续修正下一轮选题和表达。

展示边界：

- 平台名称用于证明覆盖与适配能力，不提供平台入口。
- 不展示未经确认的账号名、粉丝量、播放量、增长率或运营周期。
- 不声称所有内容必须同步发布到所有平台。
- 视觉应表达“一套内容核心，多种平台表达”，而不是平台 Logo 墙。

### 7. 工作方法

标题：

> 让内容持续发生，<br />
> 也持续被理解。

展示完整工作路径：

```text
洞察 → 策划 → 创作 → 发布 → 连接 → 复盘
```

各阶段说明：

- 洞察：理解品牌、人物、事件与社群。
- 策划：建立主题、栏目与表达结构。
- 创作：选择适合故事的内容形态。
- 发布：适配不同平台和传播场景。
- 连接：回应互动并承接真实社群。
- 复盘：沉淀反馈，修正下一轮方向。

该路径表达可持续工作方法，不使用项目管理进度条、完成度或标准交付周期。

### 8. 长期价值

标题：

> 内容最终留下的，<br />
> 不只是曝光。

收束为三项长期价值：

- 可持续积累的品牌内容资产
- 稳定、统一且具有辨识度的表达
- 品牌与真实人物、社群之间的长期连接

结尾文案：

> 让一次被看见，<br />
> 成为持续发生的关系。

正文区域不设置产品或案例跳转。页脚继续保留“返回高歌首页”和“进入高歌数字”，用于维持母品牌能力页面之间的关系。

## 导航与章节 ID

内容页章节导航不再使用“当前内容、平台矩阵、运营闭环”的旧命名。桌面端使用以下八个章节：

- 主张
- 理念
- 能力
- 实践
- 形态
- 全平台运营
- 方法
- 价值

手机端空间不足时允许将“全平台运营”缩短为“运营”，其他名称保持不变。章节导航继续单行横向滚动，不允许引起页面级水平溢出。

稳定章节 ID：

- `content-overview`
- `content-belief`
- `content-capabilities`
- `content-practice`
- `content-formats`
- `content-platform-operations`
- `content-method`
- `content-value`

继续使用 `IntersectionObserver` 更新当前章节，并沿用现有减少动态效果降级。

## 视觉方向

### 母品牌一致性

- 继续使用 `BrandPageShell`、正式品牌导航和页脚。
- 延续 `/digital` 与 `/group` 已形成的暗色材质、紧凑大标题、软圆角、低亮度边框和克制动效。
- 保留 `/content` 的暖红强调色，不改成数字页的绿色。
- 继续使用 Tailwind CSS 处理布局和常规样式；复杂主题背景、媒体偏好与跨章节表面样式保留在 `styles.css`。

### 内容页独立表达

- 真实体育、人物和社群影像是主要视觉证据。
- 内容理念与核心能力强调编辑排版，不使用通用图标卡片。
- 真实实践使用影像与能力证明组合，不表现为可点击产品卡。
- 内容形态采用节奏不一的内容墙，避免规则九宫格。
- 全平台运营以“统一内容核心向不同平台场域展开”的关系表达，避免平台 Logo 墙。
- 工作方法使用连续路径，避免六张独立功能卡。
- 长期价值使用大面积留白和收束文案结束正文。

## 交互与动效

- 首屏文字和影像只进行一次性进入，不循环播放。
- 章节内容使用透明度和小幅纵向位移表达阅读顺序。
- 章节导航保留当前项指示和锚点跳转。
- 实践案例、平台和内容形态不具有链接时，不提供 hover 上浮、箭头或按压缩放等伪点击反馈。
- 不实现轮播、自动滚动、拖拽、视差、滚动劫持或持续循环动画。
- `prefers-reduced-motion: reduce` 下移除位移、缩放和 spring，内容直接可见。
- `prefers-reduced-transparency: reduce` 和 `prefers-contrast: more` 继续使用现有品牌页降级规则。

## 数据与组件边界

继续使用 `apps/brand/src/pages/content/data.ts` 作为页面静态内容入口，但重构其语义：

- 当前 `ContentProperty` 不再承担产品状态、外链和平台标签展示。
- 内容实践数据只保留名称、摘要、能力证明与真实影像。
- 核心能力、内容形态、平台运营和工作方法分别使用清晰的静态数据结构。
- 不为本次静态品牌页引入 API 或 CMS。

建议页面私有组件职责：

- `ContentPage.tsx`：元数据、章节顺序与页面组合。
- `ContentHero.tsx`：品牌主张与首屏影像。
- `ContentBelief.tsx`：内容理念与三项内容观。
- `ContentCapabilities.tsx`：四个核心能力领域。
- `ContentPractice.tsx`：三个真实实践及能力证明。
- `ContentFormats.tsx`：内容形态墙。
- `ContentPlatformOperations.tsx`：平台覆盖和五项运营能力。
- `ContentMethod.tsx`：六阶段工作方法。
- `ContentValue.tsx`：长期价值与结尾文案。
- `ContentSectionNavigation.tsx`：八章节观察与跳转。
- `ContentSectionReveal.tsx`：章节进入和减少动态效果降级。

旧的 `CurrentContent`、`ContentPlatforms`、`ContentOperatingLoop`、`PlatformRail` 和状态展示逻辑若不再被新结构使用，可在实现时停止引用。是否删除文件以实现后的实际引用关系为准，不在设计阶段扩大清理范围。

内容页组件不得依赖数字页私有组件，其他应用和页面也不得反向依赖内容页组件。

## 元数据

页面标题从产品矩阵语义调整为能力展示语义：

- Title：`高歌内容 - 内容创作与全平台运营`
- Description：`高歌以内容策略、创作、现场表达与全平台运营，连接品牌、平台和真实社群。`

路由继续保持 `/content`。

## 响应式与可访问性

- 最小支持宽度为 320px，不产生页面级水平滚动。
- 八项章节导航在手机端保持单行可滚动，并提供边缘遮罩提示。
- 首屏在移动端先展示主张，再展示影像。
- 核心能力和真实实践在移动端变为单列，但保留明确标题层级。
- 内容形态墙在移动端允许纵向错落，不依赖精确横向拖动。
- 全平台运营在桌面端可使用中心辐射或关系布局；移动端必须转换为清晰列表，不缩小复杂关系图。
- 工作方法在移动端转换为纵向步骤。
- 不只依赖颜色表达章节、平台或能力差异。
- 所有导航和页脚链接支持键盘访问与清晰焦点环。
- 装饰影像使用空 `alt`；承载实践信息的影像使用准确且简洁的替代文本。

## 成功标准

- 访问者不会把 `/content` 误解为与 `/digital` 相同的产品目录。
- 首屏以下的主要信息用于证明内容能力，而不是引导访问产品或账号。
- 访问者能理解高歌具备策略、创作、现场表达、全平台运营、社群承接和复盘能力。
- 三个真实实践能够作为能力证据，但不暗示未经确认的产品状态或运营规模。
- 平台覆盖与全平台运营能力表达清楚，同时不成为平台入口墙。
- 页面在 320px 以上无水平溢出，并满足键盘访问和系统偏好降级要求。
