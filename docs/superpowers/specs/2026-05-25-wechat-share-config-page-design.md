# apps/admin 微信分享配置页设计

日期：2026-05-25

## 目标

为当前仓库新增一个“微信分享配置”专用配置页，使运营或管理员在暂时没有公众号真实配置条件时，后续只需在后台完成配置录入，即可让 `apps/web` 的微信内分享能力生效，无需再次改代码。

本次目标是：

- 在 `apps/admin` 提供一个“微信分享配置”后台页面
- 在 `apps/api` 提供微信分享配置的管理接口和前台读取接口
- 将当前写死在 `apps/web` 前端的分享文案和分享图来源切换为后端配置
- 保持当前“按页面区分分享内容”的范围不变
- 配置保存后立即生效

本次先完成设计，不在此文档中展开实现代码。

## 背景

当前仓库已经完成第一版微信网页分享接入，主要特点是：

- `apps/api` 已提供公众号网页 JSSDK 签名能力
- `apps/api/src/modules/wechat-share` 负责签名逻辑
- `apps/web` 已完成微信环境识别、JS-SDK 初始化和路由切换后重设分享内容
- `apps/web` 当前仍在前端静态文件中维护分享文案与分享图
- 真实公众号 `AppID / AppSecret / JS接口安全域名` 目前还没有条件配置

因此，当前问题不是“签名能力不存在”，而是“配置入口不存在”。如果等后面具备条件时再改代码，会重复进入开发流程。更合适的做法是现在把配置入口和运行时配置读取能力补齐，让后续只通过后台录入信息即可生效。

## 范围

包含：

- `apps/admin` 新增微信分享配置页
- `apps/api` 新增微信分享配置表与管理接口
- `apps/api` 新增前台可读取的微信分享配置接口
- `apps/api` 的签名服务改为优先使用数据库中的公众号配置
- `apps/web` 改为从后端读取页面分享配置
- 配置保存后立即生效
- 为新增逻辑补充必要测试

不包含：

- 通用系统配置中心
- 任意 key-value 动态配置平台
- 多公众号支持
- 多站点配置支持
- 图片上传能力
- 活动页/详情页的细粒度分享模板管理
- 非微信平台的通用社交分享中心

## 方案对比

### 方案一：新增“微信分享配置”专用配置页和专用数据模型

做法：

- 单独新增一张只服务微信分享的配置表
- 后台只提供一个“微信分享配置”页面
- 前台分享运行时只读取这份专用配置

优点：

- 与当前需求完全对齐
- 边界清晰
- 不会提前演化为通用配置中心
- 代码更容易维护和测试

缺点：

- 当前这套能力只服务微信分享
- 以后如果要扩展到其他系统配置，需要再单独设计

### 方案二：先做一个轻量系统配置中心，微信分享只是第一项

做法：

- 新增通用配置表
- 微信分享配置只是其中一个配置项

优点：

- 以后新增其他配置可能更快

缺点：

- 当前就要先解决配置命名、序列化、校验、版本演进等问题
- 容易提前抽象
- 实现复杂度明显高于当前需求

## 结论

采用方案一：新增“微信分享配置”专用配置页和专用数据模型。

具体原则：

- 本次只解决微信分享配置，不扩成系统配置中心
- 配置页只覆盖当前已确认的三个页面类型
- `AppSecret` 采用“只写不回显”模式
- 配置保存后立即生效
- 前台不再依赖前端静态写死的分享文案

## 信息架构

### 页面范围

本次配置只覆盖三类页面：

- 首页 `/`
- 球队页 `/teams/:team?`
- 资产页 `/teams/football/assets`

说明：

- 仍然沿用当前第一版的页面粒度
- 不区分足球与篮球不同的球队页文案
- 不支持详情页、活动页、动态参数级别的分享模板

### 配置结构

后台页面分两块：

#### 1. 公众号配置

字段包括：

- `AppID`
- `AppSecret`
- 默认分享图 URL

说明：

- `AppID` 必填
- `AppSecret` 默认不回显
- 默认分享图用于页面级分享图未单独填写时兜底

#### 2. 页面分享配置

每个页面类型维护一组配置：

- 标题
- 简介
- 分享图 URL

共三组：

- 首页分享配置
- 球队页分享配置
- 资产页分享配置

## 后端设计

### 模块边界

建议在现有 `apps/api/src/modules/wechat-share` 模块内继续扩展，而不是新建另一套分散模块。

原因：

- 公众号网页分享相关职责已经集中在该模块
- 配置读取和签名能力属于同一业务域
- 可以避免“配置在 A 模块，签名在 B 模块”的职责割裂

建议该模块新增：

- 配置实体
- 管理接口
- 前台公开读取接口

### 数据模型

建议新增专用表，例如：

- `WechatShareConfig`

第一版按“单记录全局配置”设计，不支持多记录和多站点。

建议字段：

- `id`
- `appId`
- `appSecret`
- `defaultImageUrl`
- `homeTitle`
- `homeDesc`
- `homeImageUrl`
- `teamsTitle`
- `teamsDesc`
- `teamsImageUrl`
- `assetsTitle`
- `assetsDesc`
- `assetsImageUrl`
- `createdAt`
- `updatedAt`

说明：

- 第一版只保留一条记录
- 后续如果要支持多站点，可再补 `siteKey`
- 当前不提前加入 `enabled`、`version`、`remarks` 等扩展字段

### AppSecret 处理规则

后台交互采用：

- 读取时不回传明文 `AppSecret`
- 返回 `hasAppSecret: true/false`
- 更新时：
  - 若 `appSecret` 缺失或为空字符串，则表示“不修改当前值”
  - 若传入新值，则覆盖原值

这样可以满足：

- 后台可维护
- 不在页面回显密钥
- 避免误覆盖

### 管理接口

建议新增后台管理接口：

- `GET /wechat/share/admin-config`
- `PUT /wechat/share/admin-config`

返回结构建议：

- `appId`
- `hasAppSecret`
- `defaultImageUrl`
- `homeTitle`
- `homeDesc`
- `homeImageUrl`
- `teamsTitle`
- `teamsDesc`
- `teamsImageUrl`
- `assetsTitle`
- `assetsDesc`
- `assetsImageUrl`

更新接口入参：

- `appId`
- `appSecret`（可选）
- `defaultImageUrl`
- `homeTitle`
- `homeDesc`
- `homeImageUrl`
- `teamsTitle`
- `teamsDesc`
- `teamsImageUrl`
- `assetsTitle`
- `assetsDesc`
- `assetsImageUrl`

### 前台公开读取接口

建议新增前台接口：

- `GET /wechat/share/public-config?path=ENCODED_PATH`

作用：

- 前台按当前路由拿到当前页应使用的分享内容

返回结构建议：

- `title`
- `desc`
- `imgUrl`

规则：

- `path === /teams/football/assets` 返回资产页配置
- `path` 以 `/teams` 开头返回球队页配置
- 其他情况返回首页配置

图片兜底规则：

- 页面级图片若为空，则回退到 `defaultImageUrl`

### 签名服务调整

当前 `wechat-share` 模块中的签名服务应调整为：

- 优先读取数据库中的 `appId / appSecret`
- 若数据库无配置，则视为分享配置未完成

不再强依赖环境变量作为正式运行来源。

建议行为：

- 若数据库中缺失 `appId` 或 `appSecret`，签名接口返回明确错误
- 前端收到错误后跳过分享初始化

说明：

- 这样后续只要在后台配置完成，即可直接生效
- 不再要求为了上线分享能力而重新部署代码

### 错误处理

后端应区分：

- 尚未配置公众号信息
- 分享页面配置不完整
- 请求参数错误
- 微信上游签名相关错误

返回原则：

- 管理接口给出明确可读错误
- 前台接口缺配置时返回明确状态
- 不向前台暴露 `AppSecret`

## 后台设计

### 路由位置

建议放在后台系统管理下，例如：

- `系统管理 / 微信分享配置`

原因：

- 当前它本质是系统级配置
- 但本次不做“系统配置中心”
- 放在系统管理下符合管理员心智

### 页面结构

页面建议使用一个主表单，分两个卡片区：

#### 1. 公众号配置卡片

字段：

- `AppID`
- `AppSecret`
- `默认分享图 URL`

交互：

- `AppSecret` 使用密码输入框
- placeholder 明确写：
  - `留空表示不修改当前 AppSecret`
- 显示 `已配置 / 未配置` 状态

#### 2. 页面分享配置卡片

按三组分块：

- 首页
- 球队页
- 资产页

每组字段：

- 分享标题
- 分享简介
- 分享图 URL

### 校验规则

第一版建议校验：

- `AppID` 必填
- 默认分享图 URL 必填，且必须是 `https://` 地址
- 每组标题必填
- 每组简介必填
- 每组分享图 URL 可选，但若填写则必须是 `https://` 地址

说明：

- 页面级分享图为空时，运行时回退到默认分享图
- 第一版不做图片上传，只填 URL

### 保存行为

保存后立即生效。

含义：

- 后台保存成功后，配置已写入数据库
- `apps/web` 下次初始化分享时直接使用新配置
- 不需要重启后端
- 不需要重新发版前端

## 前端设计

### 配置来源调整

当前 `apps/web` 前端静态配置表应改为“后端配置来源”。

前端不再在本地维护三套页面分享文案，而是在运行时读取：

- 当前页分享内容
- 当前页分享图

### 初始化流程

页面进入或路由切换后：

1. 判断是否为微信环境
2. 请求前台公开分享配置接口
3. 请求签名接口
4. 调用 `wx.config`
5. 在 `wx.ready` 中设置分享数据

说明：

- 仍保持当前全局监听路由变化的接入方式
- 仍保持“按当前页重新设置分享数据”的行为

### 配置缺失时的前端行为

如果后端尚未完成配置：

- 前端跳过微信分享初始化
- 普通页面浏览不受影响
- 控制台可输出错误日志，便于联调

这样可以满足：

- 当前没有真实公众号配置时不阻塞 H5 页面开发
- 后面补齐配置后立即可生效

## 测试设计

补充测试覆盖：

- 首次无配置时可创建配置
- 读取配置时不返回 `AppSecret` 明文
- `appSecret` 留空更新时保持原值
- 页面级图片缺失时回退默认分享图
- `path` 到页面配置的映射正确
- 签名服务优先读取数据库配置
- 配置保存后无需重启即可生效

### `apps/admin`

补充测试覆盖：

- 页面初始化能正确回显配置数据
- `hasAppSecret` 能正确显示“已配置/未配置”
- `AppSecret` 留空提交不覆盖
- 三组页面配置都能保存成功
- URL 校验能拦截非 `https://` 地址

### `apps/web`

补充测试覆盖：

- 首页能拿到首页分享配置
- 球队页能拿到球队页分享配置
- 资产页能拿到资产页分享配置
- 路由切换后重新请求并应用新页面配置
- 配置接口报错时不会阻塞页面

## 风险与后续扩展

### 已知风险

- 第一版使用单记录配置，不支持多站点
- 分享图只支持 URL，不支持后台上传
- 若公众号后台 `JS接口安全域名` 未配置，即使后台页保存完成，微信分享仍不会真正生效

### 后续可扩展方向

- 增加分享图上传能力
- 支持球队页进一步区分足球/篮球文案
- 增加活动页、详情页的细粒度模板
- 若未来确有需求，再将多类系统配置抽象为配置中心

## 实施结论

本次采用“微信分享专用配置页 + 专用配置表 + 前台运行时读取”的最小可行方案。

这样可以：

- 解决当前没有真实公众号配置入口的问题
- 保持实现边界简单
- 避免提前做通用配置中心
- 让后续只通过后台配置即可生效，无需再次改代码
