# Brand 首页导航能力说明弹窗设计

## 背景

`apps/brand` 首页顶部导航当前通过“数字、内容、体育、未来”表达高歌的品牌领域。其中数字、内容和体育会直接跳转到对应页面或站点，未来仅显示拓展状态。

本次把首页顶部导航调整为能力说明入口：用户点击领域后留在当前首页，通过弹窗了解该领域的定位与能力。

## 已确认方向

- 只调整 Brand 首页顶部导航，不改变 `/digital` 和 `/content` 正式页面的导航行为。
- 首页顶部的“数字、内容、体育、未来”全部改为按钮，点击后打开对应能力说明弹窗。
- 弹窗只承载能力说明，不提供站内或站外二次跳转按钮。
- 首页其他入口保持现状，包括首屏内数字、内容和体育的品牌入口。
- 移动端点击顶部中央“高歌”入口后可以打开弹窗，并在弹窗内切换四个能力领域。
- 第一版使用组件内静态 TypeScript 数据，不接入 API 或内容管理系统。

## 目标

1. 避免首页顶部导航点击后立即离开当前页面。
2. 用简短、可信的文案说明高歌在数字、内容、体育和未来领域的能力。
3. 保持已有视觉语言，并让桌面端与移动端都能访问能力说明。
4. 保留现有正式页面和独立站点的其他入口，不删除已有页面能力。

## 非目标

- 不删除或修改 `/digital`、`/content` 路由。
- 不修改首页首屏中的数字、内容和体育入口。
- 不调整高歌体育独立站点。
- 不引入通用弹窗库、全局状态或远程内容配置。
- 不重构与导航弹窗无关的 Brand 页面。

## 交互设计

### 桌面端

- 首页顶部导航继续显示“数字、内容、体育、未来”四个领域。
- 四个入口均使用语义化按钮。
- 入口悬停时只提亮文字，不增加独立背景色；键盘焦点使用轻量描边。
- 点击任一入口后打开居中的模态弹窗，并默认展示被点击领域。
- 弹窗内提供四个领域切换按钮，用户无需关闭弹窗即可查看其他能力。

### 移动端

- 顶部中央“高歌”标签改为可点击按钮。
- 点击后打开同一能力弹窗，默认展示“数字”能力。
- 弹窗内同样提供四个领域切换按钮。

### 关闭行为

- 点击右上角关闭按钮关闭弹窗。
- 点击弹窗外遮罩关闭弹窗。
- 按下 `Escape` 关闭弹窗。
- 弹窗打开时锁定页面滚动，关闭或组件卸载时恢复原有滚动状态。
- 弹窗关闭后不改变当前路由。

## 内容结构

每个领域由统一静态数据描述：

```ts
type CapabilityArea = 'digital' | 'content' | 'sports' | 'future'

interface CapabilityAreaInfo {
  readonly description: string
  readonly key: CapabilityArea
  readonly label: string
  readonly status: string
}
```

首版文案：

| 领域 | 状态       | 能力说明                                             |
| ---- | ---------- | ---------------------------------------------------- |
| 数字 | 产品矩阵   | 以技术与产品思维，把想法转化为面向未来的数字能力。   |
| 内容 | 内容运营   | 以创意与内容思维，把热爱转化为持续生长的影响力。     |
| 体育 | 体育生态   | 以运动与连接的力量，把热爱转化为真实发生的共同体验。 |
| 未来 | 领域拓展中 | 以好奇与行动不断探索，把未知转化为值得期待的新可能。 |

文案不使用未经证实的客户数量、用户规模、业务数据或交付承诺。

## 组件边界

继续在 `BrandNavigation` 内维护导航和弹窗状态，不新增全局状态：

- 当 `current === 'home'` 时，领域入口渲染为能力说明按钮。
- 当 `current === 'digital'` 或 `current === 'content'` 时，保留现有站内导航、体育外链和未来状态。
- 弹窗仅在首页允许打开。
- 能力数据与弹窗结构保留在导航组件附近，暂不抽取通用弹窗组件。

这一边界避免首页需求影响正式矩阵页，也不为单次使用提前建立通用抽象。

## 可访问性

- 弹窗使用 `role="dialog"`、`aria-modal="true"`、标题关联和说明关联。
- 首页领域按钮声明 `aria-haspopup="dialog"` 和当前展开状态。
- 图标按钮提供可读的 `aria-label`。
- 切换领域时用 `aria-pressed` 表达当前选项。
- 所有交互元素支持键盘焦点和键盘触发。

第一版不引入额外焦点陷阱依赖；打开弹窗时把焦点移动到关闭按钮，关闭后把焦点还给触发按钮，避免键盘用户丢失位置。

## 验证

自动化测试至少覆盖：

1. 首页四个顶部领域入口是按钮，不再是直接导航链接。
2. 点击各领域入口后路由保持 `/`，弹窗显示对应标题、状态和能力说明。
3. 弹窗内可以切换四个领域。
4. 关闭按钮、遮罩和 `Escape` 可以关闭弹窗。
5. `/digital` 与 `/content` 的顶部导航仍保持原有链接与当前领域状态。
6. 首页首屏内的数字、内容和体育入口仍保持原有目标地址。
