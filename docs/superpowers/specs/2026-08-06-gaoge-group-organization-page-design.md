# 高歌集团组织架构品牌页设计

## 背景

`apps/brand` 已包含高歌品牌首页、高歌数字产品矩阵页和高歌内容运营矩阵页，但尚未提供一个面向公众的集团组织页面。外部访客无法在同一页面理解高歌集团、高歌数字、高歌内容、高歌体育及未来领域之间的关系，也无法了解高歌体育、高歌 FC、高歌超级联赛与联赛董事会的组织结构。

本次新增公开的高歌集团组织架构品牌页。页面以品牌叙事为主，不承担内部人员管理、权限、审批或组织数据维护功能。

## 已确认方向

- 页面属于公开的集团官网品牌页面，不是内部组织管理后台。
- 新增正式路由 `/group`，不进入 `/concepts/*` 实验页面。
- 采用已确认的 A 方案“战略星图”。高歌集团位于视觉中心，产业沿轨道展开。
- 页面同时表达产业布局与管理结构，但两者分段呈现，避免把人员信息塞入主星图。
- “高歌内容”作为主显示名称，“高歌小绿本”作为别名展示。
- 第一版人员全部使用占位昵称，后续由用户提供真实昵称。
- 高歌超级联赛董事会第一版完整展示 20 席，不折叠。
- 第一版使用静态 TypeScript 数据，不接入 API、CMS 或管理后台。

## 目标

1. 让外部访客快速理解高歌集团及现有产业布局。
2. 清晰表达高歌体育、高歌 FC、高歌超级联赛之间的关系。
3. 公开呈现集团管理层、业务负责人和联赛董事会结构。
4. 建立可持续增加新产业、新业务节点和人员信息的数据结构。
5. 保持与现有高歌品牌站一致的暗色高级感，同时形成独立的集团识别。

## 非目标

- 不建设组织管理后台、人员编辑、权限、汇报关系或审批功能。
- 不接入远程组织数据接口。
- 不提供人物详情页、履历弹窗或社交媒体链接。
- 不虚构人员履历、管理头衔、业务数据或未来产业名称。
- 不修改高歌体育独立站点的页面结构。
- 不把本页私有的星图组件提前抽入共享包。

## 页面定位与视觉读法

页面读法为：面向外部访客、合作伙伴与集团成员的公开品牌组织页，采用暗色、克制、具有集团秩序感的视觉语言。

设计参数：

- `DESIGN_VARIANCE: 8`：使用不对称构图与具有记忆点的轨道关系。
- `MOTION_INTENSITY: 5`：提供克制的进入、聚焦和状态反馈动效。
- `VISUAL_DENSITY: 5`：完整展示组织信息，同时保留明显留白。

整页锁定暗色品牌主题，不在页面中切换为浅色区块。视觉基础为冷黑、银灰和低饱和鼠尾草绿。鼠尾草绿是页面唯一强调色，用于连接线、选中节点、焦点状态和少量重要文字。

## 路由与导航

Brand 应用新增正式路由：

```text
/group            高歌集团组织架构
```

现有路由保持不变：

```text
/                 高歌品牌首页
/digital          高歌数字产品矩阵
/content          高歌内容运营矩阵
/concepts         品牌视觉方案索引
/concepts/*       独立概念页面
```

正式品牌导航右侧当前为空位，新增“集团”入口。集团页需要提供可见的当前状态。现有数字、内容、体育和未来四个品牌领域继续保持在中央区域，不把“集团”混入产业领域列表。

站内链接使用 React Router。高歌体育继续使用独立站点外链，并在新标签页打开。未来领域为非交互内容。

## 页面内容结构

### 1. 集团首屏

首屏采用不对称分栏：

- 左侧展示集团名称、主张和一句简短说明。
- 右侧展示战略星图主视觉。
- 主张使用“连接热爱，生长事业”。
- 首屏背景使用一张与轨道语言一致的抽象建筑或材质图，图像保持低对比度，不干扰星图文字。

首屏必须在常见桌面视口内完整呈现主要内容。移动端改为上下排列，不缩小桌面星图后直接塞入窄屏。

### 2. 产业布局

产业布局以高歌集团为中心节点，连接四个方向：

1. 高歌数字：数字产品与服务，链接 `/digital`。
2. 高歌内容：内容品牌与运营，显示别名“高歌小绿本”，链接 `/content`。
3. 高歌体育：球队、赛事与体育生态，链接 `https://sports.gaoge.cc`。
4. 未来领域：表达持续扩展能力，无链接，不虚构子领域。

桌面端使用轨道式关系图。移动端改为纵向轨迹式结构，以清晰阅读优先。

### 3. 高歌体育结构

高歌体育作为当前最完整的业务分支单独展开，包含两个并行节点：

- 高歌 FC：集团现有球队。
- 高歌超级联赛：集团运营的赛事品牌。

高歌超级联赛继续向下连接运营负责人和 20 席董事会。页面不得把高歌 FC 表述为联赛下属球队，也不得把联赛描述为高歌 FC 的内部赛事。

### 4. 管理结构

管理结构按以下顺序展示：

1. 集团负责人 1 名。
2. 高歌数字负责人 1 名。
3. 高歌内容负责人 1 名。
4. 高歌体育负责人 1 名。
5. 高歌 FC 管理负责人 1 名。
6. 高歌超级联赛运营负责人 1 名。
7. 高歌超级联赛董事会成员 20 名。

第一版统一使用“昵称01”等明显的占位昵称。每个条目只展示昵称和职责，不展示未经确认的履历、联系方式、社交链接或照片。

管理人员不使用通用人物图标或虚构头像。没有图片时，以昵称排版形成文字席位。后续补充真实照片后，图片加载失败时仍需回退到昵称。

### 5. 未来版图

页面以开放轨道收尾，表达集团可以继续增加新领域。第一版不命名任何尚未确认的产业，也不为未来节点提供链接。

## 视觉系统

### 色彩

- 页面背景：冷调近黑色，不使用纯黑。
- 主文字：冷白与浅银灰。
- 次级文字：中性冷灰。
- 唯一强调色：低饱和鼠尾草绿。
- 不使用科技蓝霓虹、紫色光晕或多套强调色。

### 排版

- 中文继续使用品牌站现有的现代无衬线字体栈。
- 英文标识继续使用现有品牌字体。
- 集团名称和章节标题以字重、尺寸和留白建立层级，不依赖大面积渐变文字。
- 不为每个章节重复添加小型大写眉题。

### 形状与材质

- 内容容器统一使用柔和圆角系统。
- 导航与轻量操作继续使用全圆角交互形态。
- 轨道节点只在需要表达真实层级时使用边界，不把所有内容放入卡片。
- 阴影使用与背景协调的冷色阴影，避免纯黑投影。

### 媒体资源

- 实现阶段生成一张适合首屏比例的抽象建筑或材质图，视觉元素以深色金属、弧形结构和克制绿玻璃为主。
- 图片只承担氛围与材质作用，组织关系仍由真实页面组件呈现。
- 图片提供明确尺寸和替代文本，避免布局偏移。

## 交互与动效

- 首次进入时，集团核心、产业节点和连接线按层级依次出现。
- 轨道可提供非常缓慢的呼吸运动，用于表达持续生长，而不是纯装饰。
- 产业节点悬停或键盘聚焦时，高亮对应连接线和业务说明。
- 进入高歌体育章节时，视觉焦点从集团关系切换到体育内部结构。
- 人员条目提供克制的悬停和键盘焦点反馈，不做弹窗。
- 所有动效只改变 `transform` 和 `opacity`。
- `prefers-reduced-motion: reduce` 下停用自动运动和分段进入动画，保留完整结构与交互反馈。
- 不使用 `window` 滚动监听或 React state 更新连续滚动值。

## 响应式规则

### 桌面端

- 首屏采用左右不对称分栏。
- 产业关系使用完整战略星图。
- 管理层使用分组排版，董事会以完整 20 席矩阵展示。

### 平板端

- 首屏保持双栏，但减少星图尺寸和横向留白。
- 体育结构可保持双节点布局。
- 董事会根据可用宽度调整列数。

### 移动端

- 所有高变化度布局收敛为单列。
- 战略星图切换为纵向轨迹，不依赖横向拖动。
- 高歌 FC 与高歌超级联赛上下排列。
- 管理人员按组织层级依次展示。
- 董事会使用两列或三列网格，完整展示 20 名成员。
- 页面不得出现水平溢出。

## 应用内目录与组件职责

```text
apps/brand/src/pages/group/
├── GroupPage.tsx
├── data.ts
├── types.ts
└── components/
    ├── GroupHero.tsx
    ├── IndustryOrbit.tsx
    ├── SportsStructure.tsx
    ├── LeadershipStructure.tsx
    └── LeagueBoard.tsx
```

- `GroupPage`：页面编排、元信息和正式品牌页骨架。
- `GroupHero`：集团主张、媒体背景和首屏构图。
- `IndustryOrbit`：集团与产业节点的关系、跳转和响应式布局。
- `SportsStructure`：高歌体育、高歌 FC 和高歌超级联赛的结构。
- `LeadershipStructure`：集团及业务负责人的分组展示。
- `LeagueBoard`：董事会标题、人数和 20 席成员矩阵。
- `data.ts`：产业、人员、职位、状态和链接的静态配置。
- `types.ts`：本页私有的数据类型。

组件保持页面私有，不提前抽入 `packages/*`。若后续正式品牌页稳定复用相同人员展示模式，再评估抽象。

## 静态数据模型

### 产业节点

```ts
interface GroupIndustry {
  readonly alias?: string
  readonly description: string
  readonly href?: string
  readonly id: 'digital' | 'content' | 'sports' | 'future'
  readonly name: string
  readonly status: 'active' | 'future'
  readonly target?: '_blank'
}
```

### 管理人员

```ts
interface GroupLeader {
  readonly avatar?: {
    readonly alt: string
    readonly src: string
  }
  readonly id: string
  readonly nickname: string
  readonly role: string
  readonly scope: 'group' | 'digital' | 'content' | 'sports' | 'club' | 'league'
}
```

### 董事会成员

```ts
interface LeagueDirector {
  readonly avatar?: {
    readonly alt: string
    readonly src: string
  }
  readonly id: string
  readonly nickname: string
  readonly seat: number
}
```

董事会数据必须恰好包含 20 项，`seat` 为 1 到 20 的唯一整数。页面不向访客显示技术性的席位编号标签，席位字段用于稳定排序和测试。

## 元信息

- 标题：`高歌集团 - 组织与产业版图`
- 描述：`了解高歌集团旗下高歌数字、高歌内容、高歌体育及管理团队与高歌超级联赛董事会结构。`

页面卸载后不能把标题或描述错误地遗留给其他路由，继续使用 Brand 应用现有元信息能力。

## 可访问性

- 使用语义化标题层级、`section`、列表和导航元素。
- 关系图不能是唯一的信息来源，所有关系同时以可读文本结构存在。
- 可点击产业节点必须支持键盘操作与清晰焦点状态。
- 外部链接包含安全属性和明确的可访问名称。
- 未来领域渲染为非交互内容，不使用禁用链接模拟。
- 文字在背景图、半透明层和节点表面满足 WCAG AA 对比度。
- 20 名董事会成员在辅助技术中按稳定顺序读取。

## 错误与空状态

第一版没有远程数据请求，因此不设计网络加载或接口错误状态。

- 如果首屏媒体加载失败，保留暗色渐变背景和完整文字结构。
- 如果后续人员照片加载失败，回退到昵称文字席位。
- 如果管理人员数组为空，对应分组不渲染空卡片，并显示“团队信息整理中”。
- 董事会数组长度不是 20 时，开发测试必须失败，避免公开页面出现不完整席位。

## 测试与验证

### 自动化测试

- `/group` 路由渲染集团页面。
- 页面元信息正确设置并在卸载后恢复。
- 产业节点名称、别名和链接正确。
- 高歌体育、高歌 FC 与高歌超级联赛结构正确。
- 集团与业务负责人占位信息正确渲染。
- 董事会恰好渲染 20 名成员，席位顺序稳定。
- 未来领域不是可点击链接。
- 图片错误时保留昵称或文字兜底。

### 工程验证

```bash
pnpm --filter @gaoge/app-brand typecheck
pnpm --filter @gaoge/app-brand test
pnpm --filter @gaoge/app-brand build
```

### 浏览器检查

- 桌面、平板和移动端布局。
- 键盘导航和焦点状态。
- `prefers-reduced-motion` 降级。
- 首屏高度、页面水平溢出和 20 席董事会完整性。
- 浏览器控制台错误。
- 首屏图片加载失败时的回退。

## 知识库核对

开发前已查询知识库。当前 `gaoge` 仓库缺少准确源码映射，返回内容误指向其他项目；以当前仓库源码、现有 Brand 设计文档和本次用户确认内容为准。知识库未找到可用于补充集团组织架构或董事会成员信息的可靠记录，因此不从知识库推断人员与产业事实。

## 后续可扩展方向

- 用用户提供的真实昵称替换占位数据。
- 在获得授权后增加真实人物照片。
- 新增确定的产业节点和对应正式品牌页。
- 若组织信息需要频繁维护，再单独设计数据接口或内容管理能力。

这些方向不属于第一版实现范围。
