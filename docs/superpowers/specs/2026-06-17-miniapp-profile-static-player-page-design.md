# miniapp 个人页静态球员展示方案

日期：2026-06-17

## 1. 目标

将 `apps/miniapp/src/pages/profile/index.vue` 从当前“资料编辑/球员绑定”页，整体替换为截图风格的静态球员展示页。

本次目标只做页面首版视觉还原：

- 用静态数据完成页面结构与样式
- 让页面主视觉、信息层级和模块分区尽量接近截图
- 保留后续平滑替换为真实接口数据的空间

## 2. 背景

当前 `profile/index.vue` 已承载一套真实的登录态、球员绑定、头像上传和资料编辑逻辑，但用户这次的诉求不是继续扩展该逻辑，而是先把页面完全重构成一个静态球员详情展示页。

当前仓库条件如下：

- `apps/miniapp` 已具备 `Vue + uni-app + UnoCSS + SCSS` 页面实现能力
- 当前页面可以接受一次性静态重构
- 用户明确要求先不用真实数据，也不用远程图片资源

因此本次应优先关注页面视觉与布局，而不是保留旧交互链路。

## 3. 范围与非目标

### 3.1 本次范围

- 完全重写 `apps/miniapp/src/pages/profile/index.vue`
- 移除当前页内现有的绑定、上传、编辑和请求逻辑
- 在页面内写入静态球员数据
- 使用纯模板结构和局部 `scss` 完成页面视觉
- 使用纯 CSS 近似实现能力雷达图、球场示意和鞋型占位

### 3.2 非目标

- 不接任何真实接口
- 不保留旧的资料编辑和球员绑定交互
- 不新增共享组件或跨页面抽象
- 不新增远程图片依赖
- 不要求本次实现顶部状态栏、品牌角标和球员头像与截图完全像素级一致

## 4. 设计决策

### 4.1 采用单文件静态实现

页面所有静态数据、模板和样式都保留在 `profile/index.vue` 内，不额外拆分子组件。

这样处理的原因：

- 这是一次静态首版页面重构
- 组件拆分收益低于沟通与维护成本
- 能把结构、文案、样式集中在一个文件内快速调整

### 4.2 不使用远程图片，优先纯 CSS 占位

头像、背景徽记、球场、鞋型等视觉元素不依赖远程图片地址，优先使用纯 CSS 或本地简单占位方式模拟。

这样处理的原因：

- 用户明确选择“全部用本地静态占位和纯 CSS”
- 避免因为远程资源不可控影响小程序调试
- 先把版式、比例、颜色和信息层级做准

### 4.3 先做静态 tabs，不实现切换行为

页面中部的“数据 / 比赛 / 能力值 / 动态 / 资料”标签条仅实现视觉效果，默认高亮“能力值”，不接切换逻辑。

这样处理的原因：

- 当前截图只要求一个展示态
- 静态首版不需要额外引入状态和内容联动
- 后续若接真实切换，再补充最小交互即可

## 5. 页面结构

页面自上而下分为 4 个大区块。

### 5.1 顶部球员头图区

顶部区域采用深绿色大背景，包含：

- 左上返回按钮
- 中上品牌胶囊占位
- 右上更多操作占位
- 左侧圆形头像占位
- 右侧球员中英文名
- 国家、国籍、年龄、身高、体重、位置等基础信息
- 底部三列摘要数据

该区域需要加入弱化的背景徽记感，以接近截图中的俱乐部纹章氛围，但不追求完全一致。

### 5.2 标签导航区

头图区下方是白底横向标签栏，固定展示 5 个标签：

- 数据
- 比赛
- 能力值
- 动态
- 资料

其中“能力值”为默认高亮项，并带蓝色短下划线。

### 5.3 综合能力区

该区块包含：

- 标题“综合能力”
- 左上总评卡片
- 右上“生成图片”静态入口
- 中部能力雷达图
- 雷达图周围的 6 个能力值标签

能力值采用固定静态数据，例如：

- 速度：77
- 射门：84
- 传球：86
- 盘带：87
- 防守：36
- 身体素质：63
- 综合评分：86

雷达图不依赖图表库，直接用纯 CSS 绘制六边形层级和红色能力面。

### 5.4 位置介绍区

该区块包含：

- 标题“位置介绍”
- 左侧球场示意图
- 球场上的位置圆点 `ST`
- 右侧位置说明文案
- 惯用脚说明
- 左右脚鞋型占位，左脚高亮

球场示意图同样用纯 CSS 实现，不引入额外素材文件。

## 6. 数据组织

页面数据统一写在 `script setup` 内的静态对象中，至少包括：

- 球员姓名与英文名
- 国旗缩写或文字占位
- 国家与俱乐部信息
- 年龄、身高、体重、位置
- 身价、俱乐部号码、国家队号码
- 能力值数组
- 位置介绍信息

数据结构需尽量靠近未来真实详情页字段语义，但不额外抽到共享层。

## 7. 样式策略

本页样式以局部 `scoped lang="scss"` 为主，不强行全部改为工具类。

原因如下：

- 页面存在复杂背景层、伪元素和图形布局
- 雷达图、球场和鞋型占位更适合集中写样式
- 当前文件一次性定制化程度高，继续使用局部样式可读性更好

同时仍遵守现有仓库样式约束：

- 不引入新的样式框架
- 不为了抽象而抽象
- 仅在当前页内完成必要样式

## 8. 错误处理与交互约束

由于本次是纯静态页面：

- 不处理接口异常
- 不处理加载态
- 不处理登录态分支
- 返回按钮和更多按钮仅保留展示或最小导航行为

如果实现返回逻辑，优先使用现有 `CustomNavbar` 风格或 `uni.navigateBack` 最小行为；若视觉冲突明显，也可以先只保留图标展示。

## 9. 验证

本次改动属于 `apps/miniapp` 页面重构，最低验证标准为：

- `pnpm --filter @gaoge/app-miniapp typecheck`

如果类型检查之外没有合适的页面自动化验证能力，本次以类型检查作为最低完成标准，并在说明中明确未做真机视觉校验。

## 10. 验收标准

完成后应满足以下结果：

- `profile/index.vue` 已从资料编辑页替换为静态球员展示页
- 页面主结构与截图一致，包含头图区、标签栏、综合能力区和位置介绍区
- 页面内容全部来自静态数据
- 不依赖远程图片资源
- 不保留旧的绑定、上传和编辑逻辑
- 样式在小程序页面内可独立成立，并可为后续真实数据接入保留清晰结构
