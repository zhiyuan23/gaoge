# 高歌数字产品路线图页面重设计

## 背景

`apps/brand` 的 `/digital` 已经具备品牌首屏、重点产品、完整产品矩阵和交付边界，但当前页面仍接近常见的 SaaS 卡片陈列：顶部导航与长页内容缺少持续的位置感，现有产品与未来规划之间的层级不够鲜明，页面也尚未形成与 `/group` 一致的高歌母品牌气质。

本次重设计以 `/group` 作为视觉语言参考，而不是结构模板。两个页面承担不同职责：

- `/group` 介绍集团、事业部与组织关系。
- `/digital` 展示当前产品、建设中产品与未来规划产品。

因此 `/digital` 延续 `/group` 的暗色材质、鼠尾草绿、浮动胶囊导航、字体层级和克制动效，但不复用集团轨道、事业部关系图或组织介绍布局。页面信息架构改为面向产品状态和产品族的“产品路线图式品牌页”。

## 目标

- 让访问者首先看见已经运行和正在建设的真实产品。
- 清晰区分“运行中”“建设中”“规划中”，避免将规划描述为已交付能力。
- 按产品族展示未来产品，建立企业软件、消费者产品和平台能力之间的结构。
- 让 `/digital` 与 `/group` 明显属于同一母品牌，同时保持业务功能展示页自己的信息密度和浏览节奏。
- 保留现有真实产品入口、静态数据边界和状态语义。
- 在桌面、平板和移动端保持清晰层级，不产生横向溢出。

## 非目标

- 不把 `/digital` 改造成 `/group` 的结构复制品。
- 不复用集团页的产业轨道、集团组织图或人物卡片。
- 不新增产品详情路由、筛选、搜索、排序、分页或时间轴日期。
- 不接入 API、CMS、远程配置或后台管理。
- 不新增虚构产品截图、客户案例、用户数据或经营指标。
- 不改变现有产品状态、外链目标和产品之间的独立交付边界。
- 不调整 `/group`、`/content`、首页或体育站点。
- 不引入新的动画、图标或 UI 依赖。

## 页面定位与核心文案

英文标识保持：

> GAOGE DIGITAL

中文主张调整为：

> 让复杂业务，运行得更清晰。

辅助说明：

> 以技术与产品思维，把真实需求转化为持续演进的数字产品。

新主张保留现有“清晰系统”的含义，但强调产品投入真实业务后的持续运行，更适合承接当前产品与未来规划的完整叙事。

## 页面信息架构

页面按以下顺序组织：

1. 浮动品牌与章节导航
2. 产品主张首屏
3. 当前产品
4. 未来产品规划
5. 产品交付方式
6. 页脚

首屏回答“高歌数字做什么”，当前产品回答“现在有什么”，未来规划回答“接下来向哪里发展”，交付方式回答“这些产品以什么边界被提供”。

## 母品牌视觉继承

### 延续内容

- 页面使用 `/group` 的深黑绿色背景、低饱和鼠尾草绿强调色、冷白正文和银灰辅助文字。
- 顶部导航采用 `/group` 的 sticky 浮动胶囊材质，包括半透明深色背景、背景模糊、内高光和柔和阴影。
- 大标题使用紧凑字距与较短行高；正文保持舒适行距。
- 交互控件在按下时立即提供轻微缩放反馈。
- 章节进入采用一次性、无弹跳的淡入与轻位移。
- 所有动效提供减少动态效果降级，透明材质提供减少透明度与增强对比度降级。

### 不继承内容

- 不使用集团首屏的产业轨道与中心节点。
- 不复制事业部、管理层、董事会或愿景模块的布局。
- 不以集团组织关系解释产品矩阵。

`/digital` 的首屏右侧改为抽象的“产品工作台层叠场景”：用界面框架、产品名称、真实状态和简化结构表达数字产品感，但不绘制不存在的业务数据或虚构后台页面。

## 顶部导航

`BrandNavigation` 在 `/digital` 下采用与 `/group` 同体系的浮动胶囊外观，并提供页面内章节导航：

- 概览
- 当前产品
- 产品规划
- 交付能力

导航要求：

- 保留 GAOGE 首页入口和当前“数字”区域标识。
- 使用 `IntersectionObserver` 更新当前章节。
- 当前项使用与 `/group` 一致的短下划线或高亮指示器。
- 桌面显示完整四项；窄屏允许横向滚动或收敛标签，但不能换成两行。
- 点击章节使用锚点滚动；减少动态效果时使用即时跳转。
- 导航始终保持一行，并避免与 320px 最小宽度冲突。

章节导航能力应作为数字页私有组件实现。只有当后续其他正式品牌页确认复用同一行为时，才评估抽象为通用品牌章节导航。

## 产品主张首屏

首屏使用非对称两列布局：

- 左侧展示英文标识、中文主张与一句辅助说明。
- 右侧展示产品工作台层叠场景。

产品场景以高歌跨境 ERP 为视觉主体，并提供“持续交付”辅助面。场景用于表达已有产品、产品状态和持续演进，不承担点击入口；真实产品入口放在后续“当前产品”模块中。

首屏必须在常见桌面视口内完整呈现。移动端改为上下结构，先显示主张，再显示简化后的产品场景；不使用固定 `100vh`，使用动态视口单位或基于导航高度的最小高度。

## 当前产品

当前产品模块只展示状态为 `live` 或 `building` 的三项产品：

1. 高歌跨境 ERP：运行中，作为主要产品。
2. 高歌 Club：建设中。
3. 高歌客户 CRM：建设中。

布局使用不对称 `1 + 2`：

- 高歌跨境 ERP 占据主要区域，展示名称、英文名、摘要、状态、标签和真实外链入口。
- 高歌 Club 与高歌客户 CRM 使用两个次级产品面，信息更紧凑。
- 主要产品可以使用已有 `MediaWithFallback` 或抽象产品界面承载视觉；没有真实素材时不得伪造截图。
- 只有存在 `href` 的产品渲染为链接；建设中产品保持语义化只读内容，不提供伪点击反馈。

运行状态使用现有 `MatrixStatus` 语义。可点击产品提供 hover、focus-visible 和 pointer-down 反馈；只读产品不使用上浮效果暗示点击。

## 未来产品规划

未来规划模块只展示状态为 `planned` 的产品，并按产品族分组：

### 企业软件

- 高歌通用 ERP
- 高歌内容 CMS
- 高歌协同 OA
- 高歌洞察 BI

### 消费者产品

- 赛事与会员
- 票券与现场服务

### 平台能力

- 身份与权限
- 工作流与数据
- AI 与连接器

规划内容采用分组目录或路线图式横向行，不使用九张完全相同的卡片。每一行由产品族名称、该族产品名称与一句摘要、统一的“规划中”状态构成。

不展示未经确认的发布时间、季度、优先级或进度百分比。“规划中”只表示方向已进入产品矩阵，不承诺交付日期。

`多端交付` 当前状态为 `building`，它属于交付能力而不是独立终端产品，因此从产品规划列表中移入后续交付模块。

## 产品交付方式

末段以简洁的横向信息带收束页面，展示：

- 独立产品
- 共享平台能力
- 独立部署与专属云
- 多端交付
- 后续 SaaS

该模块不使用新的卡片矩阵，不重复产品列表。核心表达为：

> 清晰边界，持续演进。

文案保持现有产品边界：高歌跨境 ERP、高歌通用 ERP 和其他产品是独立产品，不描述为同一系统的不同模块。

## 数据与组件边界

继续使用 `apps/brand/src/pages/digital/data.ts` 作为数字页静态数据的唯一入口。现有 `DigitalProduct` 模型足以支持本次页面，不新增后端字段。

建议组件职责：

- `DigitalPage.tsx`：页面编排、元数据与章节组合。
- `DigitalSectionNavigation.tsx`：数字页章节观察、当前项与锚点交互。
- `DigitalHero.tsx`：主张与产品工作台场景。
- `CurrentProducts.tsx`：运行中和建设中产品的 `1 + 2` 展示。
- `ProductRoadmap.tsx`：规划产品的产品族分组目录。
- `DigitalDelivery.tsx`：交付边界信息带。
- `DigitalSectionReveal.tsx`：一次性章节进入与 reduced-motion 降级；若实现足够简单，也可以由各节直接使用 Motion 而不增加组件。

现有 `FeaturedProduct.tsx` 和 `DigitalDirectory.tsx` 可以在不再适合新结构时停止渲染，但不因本任务强制删除。避免为了复用而让集团页组件依赖数字页，或让数字页直接依赖集团页私有业务组件。

## 交互与动效

- 首屏文字与产品场景使用一次性无弹跳 spring 或等价的流畅进入，响应约 `0.35–0.45s`。
- 章节进入只使用透明度与小幅 `y` 位移，禁止持续循环动画。
- 导航当前项指示器使用 `bounce: 0` 的可重定向 spring，从当前屏幕位置移动。
- 外链产品在 pointer-down 时立即缩放到约 `0.985`，释放后恢复。
- 不实现拖拽、轮播、自动播放、视差、橡皮筋或复杂滚动劫持。
- 进入与退出沿同一路径，交互过程中不锁定输入。

## 响应式与可访问性

- 页面最小支持宽度为 320px，无横向页面滚动。
- 首屏两列在小于 768px 时变为上下布局。
- 当前产品 `1 + 2` 在移动端变为单列，主产品仍保持最高信息层级。
- 产品规划每一行在移动端变为“产品族名称 → 产品清单 → 状态”的纵向结构。
- 导航、真实产品链接和页脚入口均支持键盘访问与清晰焦点环。
- 不只依赖颜色表达状态，继续展示状态文字。
- `prefers-reduced-motion: reduce` 下取消位移和 spring，仅保留极短淡化或即时状态。
- `prefers-reduced-transparency: reduce` 下导航与产品表面使用近实色背景并移除模糊。
- `prefers-contrast: more` 下提高边框、辅助文字、状态与焦点环对比度。

## 测试与验证

自动化测试覆盖：

- `/digital` 元数据保持正确。
- 当前产品区只展示一个 `live` 和两个 `building` 产品。
- 高歌跨境 ERP 保留真实外链及新窗口安全属性。
- 建设中和规划中产品不产生空链接。
- 未来规划区只展示 `planned` 产品，并按企业软件、消费者产品和平台能力分组。
- `多端交付` 出现在交付能力，而不是规划产品目录。
- 章节导航链接到概览、当前产品、产品规划和交付能力四个稳定 ID。
- 状态文字不只通过颜色表达。
- 减少动态效果时章节与导航仍可正常使用。

```bash

```

浏览器检查：

- 1440×900：首屏完整、导航单行、当前产品层级和规划分组清晰。
- 1024×768：导航不换行，产品场景与文字比例合理。
- 390×844：首屏上下布局、规划目录可读、无横向溢出。
- 320×800：导航与产品名称不截断关键含义。
- 键盘：导航、Compass 外链和页脚入口的焦点顺序与焦点环正确。
- 系统偏好：减少动态效果、减少透明度和增强对比度均有明确降级。

## 成功标准

- 访问者无需阅读完整页面即可区分当前产品与未来规划。
- `/digital` 与 `/group` 在色彩、材质、导航和动效上属于同一品牌体系，但页面布局不会被误认为集团页复制。
- 当前产品状态和真实入口明确，建设中产品没有错误点击暗示。
- 规划产品按产品族清晰呈现，并且没有虚构日期或进度。
- 页面在 320px 以上无横向溢出，键盘与系统偏好降级可用。
