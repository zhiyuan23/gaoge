# 高歌集团页数字产品展示设计

## 背景

`apps/brand` 的 `/group` 页面已经依次展示集团首屏与四个事业部、高歌体育、集团管理层、联赛董事会和集团愿景。页面虽然在事业部结构中提到“高歌数字”，但没有继续展开具体产品，也没有直接向潜在客户说明高歌数字能够提供哪些方向的数字产品。

本次在集团首屏之后、高歌体育之前增加独立“高歌数字”模块。模块整体沿用当前高歌体育的标题层级、暗色卡片语言和克制交互，以一张主卡和两张小卡展示 Gaoge Compass、Gaoge CRM 与 Gaoge Club，并补充一组面向客户的能力方向。

当前工作区存在与 `/group`、品牌导航、首页交互和全局样式重叠的未提交修改。实施必须以这些内容为在途成果，只做增量调整，不回退、不覆盖、不顺带提交无关改动。

## 目标

- 在 `/group` 中建立与“高歌体育”并列的“高歌数字”独立展示模块。
- 明确 Gaoge Compass 是当前重点产品，Gaoge CRM 与 Gaoge Club 是两项辅助展示产品。
- 让三张产品卡都可以直接进入各自演示环境。
- 用简洁、客户可理解的语言展示高歌数字能够提供的产品方向。
- 保持集团页现有视觉体系、响应式和无障碍标准。

## 不在范围内

- 不修改 `/digital` 页的页面结构、完整产品矩阵或产品状态体系。
- 不修改 Gaoge Compass、Gaoge CRM、Gaoge Club 三个独立系统。
- 不新增 API、CMS、后台配置、数据库、埋点或第三方依赖。
- 不新增产品截图、虚构客户案例、价格、联系方式或销售表单。
- 不扩大 CRM 与 Club 的公开功能承诺，文案只使用已确认的产品方向。
- 不重构高歌体育、集团管理层、联赛董事会或集团愿景模块。

## 页面位置与结构

调整后的 `/group` 页面顺序为：

1. 顶部品牌导航
2. 集团首屏与四个事业部
3. 高歌数字
4. 高歌体育
5. 集团管理层
6. 联赛董事会
7. 集团愿景
8. 页脚

高歌数字模块是独立语义化 `section`。它不嵌入集团首屏的事业部轨道，也不与高歌体育共用数据或组件，以便两个事业模块保持各自清晰的产品边界。

## 模块标题与介绍

标题区沿用高歌体育模块的结构与字阶：

- 引导语：`以数字连接业务`
- 主标题：`高歌数字`
- 说明：`从真实业务出发，把复杂流程变成清晰、可持续使用的数字产品。`

标题区与内容容器继续使用集团页现有的 `max-w-7xl`、移动端 `px-6`、桌面端 `md:px-10` 和相同纵向节奏，不引入新的页面宽度。

## 产品展示

### 布局

桌面端采用“一主两辅”布局：

- Gaoge Compass 使用主卡，占据较大的视觉面积并跨越两行。
- Gaoge CRM 与 Gaoge Club 使用两张较小的辅助卡，在主卡一侧纵向排列。
- 视觉层级通过卡片面积、字号和背景层次表达，不使用夸张动画。

移动端按以下顺序切换为单列：

1. Gaoge Compass
2. Gaoge CRM
3. Gaoge Club

所有卡片沿用高歌体育模块的圆角、细边框、暗色表面、右上角外链图标、轻微悬浮位移和键盘焦点描边。模块可以使用独立类名表达主卡与辅助卡的背景差异，但不得改变现有高歌体育卡片样式。

### 产品内容

三张卡统一展示英文产品名、中文定位、简短说明和“演示系统”标识。

#### Gaoge Compass

- 英文名：`GAOGE COMPASS`
- 中文定位：`高歌跨境 ERP`
- 说明：`连接订单、商品、库存、履约、财务与经营分析，让跨境电商业务在一套系统中清晰协同。`
- 地址：`https://compass.gaoge.cc?demo`
- 层级：主卡

该说明以当前已实现的跨境电商 ERP 能力为依据，不将 Gaoge Compass 描述为通用 ERP。

#### Gaoge CRM

- 英文名：`GAOGE CRM`
- 中文定位：`高歌客户 CRM`
- 说明：`围绕线索、客户、商机与跟进过程，帮助销售团队持续记录和推进客户关系。`
- 地址：`https://crm.gaoge.cc?demo`
- 层级：辅助卡

该说明只表达已确认的 CRM 产品闭环方向，不宣称尚未验证的具体交付状态。

#### Gaoge Club

- 英文名：`GAOGE CLUB`
- 中文定位：`高歌 Club`
- 说明：`面向会员、活动与社群关系，让俱乐部的连接、参与和日常运营更顺畅。`
- 地址：`https://club.gaoge.cc?demo`
- 层级：辅助卡

知识库目前只有 `gaoge-club` 仓库来源记录，没有可靠的公开产品说明，因此该文案沿用 `/digital` 已确认的会员、活动与社群方向，不从仓库名推断更多功能。

### 跳转行为

- 三张产品卡都渲染为外部链接。
- 全部使用 `target="_blank"` 与 `rel="noopener noreferrer"`。
- 无障碍名称包含产品中文定位、“进入演示系统”和“将在新窗口打开”。
- 地址必须保留裸查询参数 `?demo`，不改写为内部路由或其他查询键。

## 客户能力方向

产品卡下方增加“我们可以提供”能力带，用于让潜在客户快速理解高歌数字可以承接的产品方向。能力带包含四项：

| 能力方向           | 对外说明                                                       |
| ------------------ | -------------------------------------------------------------- |
| 企业管理系统       | 围绕经营、销售、库存、履约与协作，构建贴合业务流程的管理产品。 |
| 客户与会员运营     | 连接线索、客户、会员、活动与服务，形成可持续运营的数字触点。   |
| 业务流程与数据协同 | 梳理跨部门流程，连接已有系统与数据，让信息流转更清晰。         |
| 多端交付与独立部署 | 支持 Web、桌面、移动与小程序，并可按需要提供独立部署。         |

能力带采用轻量文本布局，不再增加第四张产品卡，也不使用“万能平台”“全行业解决方案”等超出当前边界的宣传措辞。

## 数据与组件边界

- `apps/brand/src/pages/group/types.ts` 新增页面私有的数字产品与能力方向类型。
- `apps/brand/src/pages/group/data.ts` 继续作为 `/group` 静态内容的唯一数据入口，新增三项产品数据与四项能力数据。
- 新增 `apps/brand/src/pages/group/components/DigitalStructure.tsx`，只负责高歌数字模块的语义结构、产品卡和能力带渲染。
- `apps/brand/src/pages/group/GroupPage.tsx` 只负责导入数据并把 `DigitalStructure` 插入 `GroupHero` 与 `SportsStructure` 之间。
- 不从 `/digital` 页面直接导入产品数据，避免集团页对完整产品矩阵的状态与字段结构产生不必要耦合；两页文案需要保持事实一致，但展示目的与数据契约独立。
- 不抽取跨页面或跨应用共享组件。

## 视觉与交互

- 延续集团页的黑色、银灰和鼠尾草绿体系，不新增品牌主题色。
- 主卡可以使用更明显但克制的径向渐变或细网格纹理；辅助卡使用更安静的表面层次。
- 悬浮只使用轻微上移、边框增强和外链图标提亮。
- 点击区域覆盖整张产品卡。
- 不新增自动播放、视差、持续循环动画或需要 JavaScript 管理的复杂动效。
- `prefers-reduced-motion` 下依赖现有全局策略关闭非必要位移。

## 可访问性与响应式

- `section` 通过 `aria-labelledby` 关联“高歌数字”标题。
- 能力方向使用列表语义，产品卡的文字信息不依赖颜色或背景区分。
- 外链图标作为装饰元素对辅助技术隐藏。
- 键盘访问时三张链接都有清晰焦点状态。
- 窄屏下所有卡片和能力项按文档顺序单列，不出现横向滚动。
- 中长中文说明允许自然换行，不使用固定高度截断正文。

## 测试与验证

自动化测试覆盖：

- 集团页在高歌体育之前展示“高歌数字”。
- 三项产品数据名称、主辅层级和地址完全符合设计。
- 三张卡都使用对应的 `?demo` 地址、新窗口和安全 `rel` 属性。
- Gaoge Compass 主卡与两张辅助卡使用可识别的布局类或测试标识。
- 页面展示“演示系统”标识、三段产品说明和四项能力方向。
- 移动端渲染顺序保持 Compass、CRM、Club。
- 原有高歌体育外链、集团管理层、联赛董事会和集团愿景继续存在。
