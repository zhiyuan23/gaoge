# Admin 菜单与权限工作区参考对齐设计

- 日期：2026-08-26
- 状态：待实施
- 范围：`apps/admin` 菜单与权限工作区，以及内置 Resource 展示说明

## 背景

当前目标仓的菜单与权限工作区虽复用了同一组件，但“菜单结构 / 资源目录”切换额外同步到路由 query，旧权限地址也跳转到带 `view=resources` 的 URL。该行为让路由和页面页签系统把工作区内部切换识别为页面导航，与参考系统仅切换组件本地状态的行为不同。

目标仓还为所有内置 Resource 自动生成“某模块的某资源”说明，因此流言板 Resource 详情展示了“内容模块的流言板动态资源”。参考系统没有这类机械生成的提示，应保持一致并移除。

## 目标行为

- “菜单结构 / 资源目录”在同一个 `/system/menu` 页面内切换。
- 切换只更新组件本地状态，不改变当前路由或 query，不产生新的页面跳转或页签记录。
- 旧 `/system/permission` 仅作为兼容入口跳转到 `/system/menu`，不指定工作区模式。
- 内置 Resource 不再自动生成“某模块的某资源”说明；没有明确说明时，详情区域不展示提示文案。

## 实现方案

### 同页切换

菜单与权限工作区保留现有单组件结构和两种模式。移除对 `useRoute`、`useRouter`、路由 query 监听及 `router.replace` 的依赖，让模式默认从“菜单结构”开始，并由现有切换控件在组件内部更新。

兼容路由 `/system/permission` 继续保留，但直接重定向到命名路由 `systemMenu`。不新增路由、不拆分组件，也不改变服务端菜单与权限投影。

### Resource 提示

内置 Resource 构造时不再拼接通用说明，默认使用空说明。现有详情模板已经按说明是否存在决定是否渲染，因此同步内置配置后，“内容模块的流言板动态资源”等机械提示会自然消失。

自定义 Resource 及后续显式维护的说明字段继续保留；本次不删除数据库字段，也不改变 Resource API 契约。

## 验证

- 添加或调整前端静态回归检查，确认工作区不再读取或写入 `route.query.view`，兼容权限路由不再携带 query。
- 添加或调整 RBAC 内置定义测试，确认内置 Resource 默认说明为空。
- 运行相关 Admin 测试、API RBAC 测试、Admin/API 类型检查或构建，以及 `git diff --check`。
- 必要时同步本地内置配置并手动检查：两种模式同页切换且 URL 不变，流言板 Resource 详情不显示机械提示。

## 本次不做

- 不修改 Resource、Permission、Menu 数据模型或 API 契约。
- 不修改权限码、角色授权、导航可见性语义或审计逻辑。
- 不删除旧权限页面文件，仅保留路由兼容行为。
- 不清理与本次修正无关的现有工作区改动。
