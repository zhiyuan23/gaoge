# Brand 集团页转场与滑动指示优化设计

日期：2026-08-09

## 背景

首页上滑进入 `/group` 已具备连续拖动、滚轮累积、速度投影与回弹能力，但完成动画后仍可能出现一次闪烁。当前 `/group` 使用懒加载，路由切换时存在进入 Suspense fallback 的机会；同时首页中的集团预览与真实集团首屏结构不同，替换 DOM 时会产生明显的视觉接缝。

底部“上滑了解高歌集团”胶囊同时占据较大的视觉面积，与全屏视频、主标题和四个能力信号竞争注意力。本次优化只处理转场交接与入口视觉，不改变手势阈值、集团页内容或站点导航结构。

## 已确认方向

- 采用“提前预载 + 首帧交接层淡出”的方案消除路由加载空档和 DOM 替换跳变。
- 不仅取消懒加载，也保证新路由首帧延续滑动动画的末帧。
- 桌面端把底部胶囊改为约 24px 的轻量上向尖头，保留克制的方向提示动画。
- 手机竖屏使用更小、静态的指示；矮屏和手机横屏直接隐藏视觉提示。
- 视觉元素缩小后仍保留足够点击热区、键盘操作与无障碍名称。

## 根因与目标

### 根因

1. `GroupPage` 是动态导入路由，手势完成后才触发模块解析时可能短暂显示黑色 Loading。
2. `GroupTransitionPreview` 只有集团背景与左侧文案，真实集团首屏还包含导航、不同高度约束和组织结构图；两棵 DOM 树在路由切换时直接替换。
3. 当前底部按钮把文字、短横线、玻璃背景和 44px 高度都做成可见表面，视觉重量超过其辅助导航角色。

### 目标

1. 动画末帧到 `/group` 首帧之间不出现黑屏、亮度闪跳或布局跳变。
2. 真实集团首屏挂载后以短促交叉淡化接管画面，避免重复播放冲突的入场动画。
3. 滑动提示退到背景层级，不再挤压或遮挡首页其他元素。
4. 维持现有触摸、滚轮、点击、键盘与减少动态效果行为。

## 方案比较

### 方案 A：提前预载并使用交接层（采用）

首页挂载后预载集团路由模块。动画完成并导航时，集团页首帧继续覆盖与动画末帧一致的预览层；真实首屏在其下方完成挂载，随后交接层用约 160ms 淡出。该方案同时解决加载空档与视觉不一致，且可以渐进降级。

### 方案 B：仅把集团页改为同步导入

可以消除 Suspense fallback，但无法消除预览层与真实页面结构不同造成的画面跳变，不足以解决完整问题。

### 方案 C：浏览器 View Transition API

可以提供文档级快照过渡，但支持情况、路由集成和系统偏好控制更复杂。当前只有一个入口需要连续交接，引入成本高于收益。

## 转场交接设计

### 预载

- 将集团页动态导入封装为可复用加载函数，React lazy 路由与首页预载调用共享同一个 Promise/模块缓存。
- 首页组件挂载后在 effect 中启动预载，不阻塞首屏渲染，也不等待用户手势完成后才发起加载。
- 加载失败不阻断现有导航；正式路由仍由 Suspense fallback 和浏览器错误路径处理。

### 路由状态

首页完成滑动后继续通过 location state 传递 `fromHomeTransition: true`。只有该来源启用交接层；直接访问、刷新、浏览器历史进入 `/group` 不显示额外覆盖层。

### 首帧交接层

- 集团页在从首页进入时，首个 render 同步绘制一个 fixed、不可交互、`aria-hidden` 的集团预览覆盖层。
- 覆盖层复用动画末帧所用的 `GroupTransitionPreview`，保证路由切换前后首帧像素结构一致。
- 真实 `BrandPageShell` 和 `GroupHero` 同时在覆盖层下方挂载；`GroupHero` 跳过自身入场动画。
- 连续两个 `requestAnimationFrame` 后，确认新页面至少完成一次布局与绘制，再把覆盖层用约 160ms 的透明度变化淡出并卸载。
- 交接层仅改变 `opacity`，不再移动整屏；设置 `pointer-events: none`，不会延迟用户接管新页面。
- 组件卸载时取消待执行的 animation frame，避免历史导航产生陈旧更新。

### 减少动态效果

`prefers-reduced-motion: reduce` 下不执行整屏滑动，也不播放指示动画。导航后的交接层可以直接省略，或只做不超过 100ms 的透明度淡化；默认采用直接省略，避免额外大面积运动。

## 底部指示设计

### 桌面端

- 移除可见胶囊背景、描边、阴影和文字。
- 使用两条细线构成约 24×12px 的上向 chevron，颜色保持低对比白色。
- 点击与拖动按钮仍使用至少 44×44px 的透明命中区域，光标与 focus-visible 反馈保留。
- 仅在支持 hover 且未请求减少动态效果的设备上播放克制循环：尖头上移约 3px 后回到原位，完整周期约 1.8–2.2s，并包含明显静止段。
- hover、focus-visible 或 pointer down 时提高对比度，不增加新的大面积材质。

### 手机竖屏

- 不显示文字，chevron 缩小至约 18×9px。
- 默认静止，不播放循环动画，避免与视频和底部能力信号叠加。
- 保留 44×44px 透明触控区域，并继续作为上滑起点。
- 位置保持在安全区和底部能力信号上方，避免视觉重叠。

### 矮屏与手机横屏

- 隐藏 chevron 的可见图形，但保留右上角集团链接作为清晰入口。
- 底部透明按钮不再占据视觉空间；为避免不可见控件形成意外点击区，矮横屏下同时停用其 pointer events。

## 组件边界

- `App.tsx` 或独立路由加载模块：提供共享的集团页加载函数，供 lazy route 与预载复用。
- `SkiingHero.tsx` / `GroupSwipeEntry.tsx`：在首页生命周期中触发预载；手势物理逻辑不变。
- `GroupTransitionPreview.tsx`：继续作为动画末屏，并允许在集团页交接层中复用；保持无交互、不可访问。
- `GroupPage.tsx`：根据 location state 控制交接层生命周期。
- `GroupHero.tsx`：继续在首页转场来源下跳过重复入场动画。
- `styles.css`：负责轻量 chevron、设备适配、focus 状态与减少动态效果。

不引入全局状态、新依赖或跨应用共享包。

## 测试与验证

自动化测试覆盖：

1. 首页挂载后会预载集团页模块。
2. 从首页转场进入集团页时首帧存在不可交互的交接层。
3. 交接层在两个绘制帧后开始淡出并最终卸载。
4. 直接访问集团页不创建交接层。
5. 从首页转场进入时集团 Hero 仍跳过重复入场动画。
6. 底部按钮保留按钮语义、无障碍名称、点击和拖动行为，视觉文字被移除。
7. 减少动态效果下不播放交接层与指示循环动画。

浏览器手动检查：

- 使用网络节流从首页上滑进入 `/group`，确认不出现 Loading 黑屏。
- 逐帧观察动画末帧、URL 改变和集团页接管过程，确认背景与文案无闪跳。
- 在 1440×900、390×844、320×800 和手机横屏检查指示尺寸、位置及与能力信号的关系。
- 验证桌面点击、键盘 focus、触摸拖动、滚轮累积、弹层禁用和浏览器返回。
- 开启减少动态效果，确认没有整屏滑动、循环位移或额外交接动画。

完成前运行 brand 测试、typecheck、build、ESLint、Stylelint、Prettier 和 `git diff --check`。

## 成功标准

- 正常网络与节流网络下，从滑动末帧进入 `/group` 都没有可感知的黑屏或闪烁。
- 集团页的真实内容以短促、平滑的透明度交接出现，不重复从下方或缩放入场。
- 桌面底部只出现克制的方向提示；手机端更弱，矮横屏无可见提示。
- 缩小视觉元素不降低点击热区、键盘可达性或手势成功率。
- 现有 77 项测试及新增回归测试通过，其他 Brand 页面与直接访问 `/group` 行为不变。
