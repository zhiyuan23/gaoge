# Admin 应用配置弹窗化设计

> **状态：已实施并验证。** 实现提交为 `d9567ea`，当前版本使用 CSS 双栏布局，不包含 `ResizeObserver` Masonry。

## 背景

`apps/admin` 的开发模式应用配置原本通过右侧 `FaDrawer` 展示。参考项目 Fantastic Admin 已将该入口调整为宽弹窗，并把较长的配置内容整理为双栏卡片布局。

当前项目已把外层容器替换为 `FaModal`，并将原有单列长表单整理为桌面双栏、移动单栏的卡片布局，减少滚动距离并提高模块辨识度。

## 目标

- 点击现有应用配置入口后，以居中弹窗展示配置内容。
- PC 模式下使用左右两栏，移动模式下使用单栏。
- 使用现有 `FaPageMain` 为每个配置模块提供标题栏、卡片背景、边框和圆角。
- 结合当前项目实际配置项归并相关模块，减少重复标题和零散区块。
- 保留所有配置值绑定、实时预览、复制配置、提示信息和事件逻辑。
- 保留导航工程底座设置，包括“无主导航模式隐藏一级菜单”和“导航模式切换”。

## 非目标

- 不升级 Fantastic Admin 或批量同步其最新源码。
- 不调整 Pinia 配置状态、事件总线或应用配置入口。
- 不新增、删除或改变任何配置项的业务语义。
- 不修改通用 `FaModal`、`FaDrawer` 或 `FaPageMain` 组件 API。
- 不引入 `ElDialog`、新组件或新的样式依赖。
- 不实现尚处于后续设计阶段的 fade-only 动画和横向 Masonry。

## 组件与布局

仅修改 `apps/admin/src/layouts/components/AppSetting/index.vue`。

### 弹窗

- 保留现有 `FaModal`、`v-model="isShow"`、标题、描述和 footer 条件。
- 保留 `sm:max-w-4xl` 桌面宽度。
- 为弹窗内容区设置主区域背景色，并继续使用现有滚动容器。
- 内容区不再放置临时配置提示，配置卡片从内容区顶部直接开始。
- footer 使用全宽纵向布局：临时配置提示位于上方，“复制配置”按钮位于下方。
- 提示文案居中显示，使用语义化玫红色背景和文字；`src/settings.ts` 使用等宽字体与弱背景突出。

### 双栏容器

- 当 `settingsStore.mode === 'pc'` 时使用两栏。
- 当 `settingsStore.mode === 'mobile'` 时使用一栏。
- 当前实现使用 CSS `columns-2`/`columns-1`，内容按纵向列流动；没有网格行跨度测量。
- 弹窗内容区沿用现有内边距，列间距和卡片纵向间距统一采用 16px 节奏。
- 每张卡片使用 `break-inside-avoid`，避免同一卡片被拆分到两栏。
- 不引入横向滚动。

### 卡片样式

每个一级模块使用 `FaPageMain`：

- 外层移除默认页面边距，保留一条连续的完整边框和顶部、底部圆角，使用统一的底部间距，并以 `secondary` 作为标题圆角背后的底色。
- 标题栏使用 14px 字号、16px 行高、10px 上下内边距和 16px 左右内边距，使标题区域保持紧凑。
- 标题文字加粗并使用次级文字色，标题栏背景使用语义化 `secondary` 表面色，与白色正文区形成清晰但克制的深浅层级。
- 标题栏不再单独绘制边框，而是复用外层的顶部和左右连续边框；正文区域向标题方向衔接 1px，仅绘制带顶部圆角的上边界，形成参考截图中的白色圆角面板覆盖在深色标题背景上的效果。
- 内容区继续使用 `bg-card` 和统一的纵向间距。
- 由 `FaPageMain` 提供 `bg-card`、边框、圆角和主题过渡，兼容明亮与暗黑模式。
- 明亮与暗黑模式均由卡片外层绘制唯一连续轮廓；正文不绘制左右和底部边框，避免出现双边框或连接错位。
- 正文顶部圆角外侧显示外层的 `secondary` 背景，不再露出白色；正文底部由外层圆角、边框和 `overflow-hidden` 统一收口。
- 标题栏颜色只通过现有语义主题类实现，明亮与暗黑模式均不写固定色值。
- 移除原有 `FaDivider`，避免卡片标题和分隔标题重复。

### 配置行密度

- 普通配置行仅使用 `flex`、居中对齐、两端分布和 16px 横向间距，不再额外添加行级上下内边距、背景色、圆角或 hover 背景。
- 行间距统一由卡片内容区的 `space-y-4` 提供，使开关、按钮、输入框和标签保持一致的视觉节奏。
- 标签保持 14px 字号，帮助图标继续使用现有橙色提示样式。
- 导航模式预览区只保留居中和 16px 间距，移除额外底部内边距。

### 小尺寸连接式单选按钮

- 颜色主题风格、圆角系数、主导航点击模式和顶栏模式统一使用现有 `FaButton` 的 `sm` 尺寸。
- 同一组互斥选项紧密连接，不保留选项间距；首项和末项分别保留外侧圆角，相邻按钮边框重叠 1px，形成参考项目中的分段按钮组。
- 当前选中项继续使用 `default` 变体，未选中项使用 `outline` 变体，并提高选中项层级，避免连接处边框覆盖选中态。
- 颜色主题风格保留现有图标、文字和配置值，仅将 `FaTabs` 的展示方式替换为小尺寸连接按钮。
- 圆角、主导航点击模式和顶栏模式保留现有选项数组、点击赋值和文字内容。
- 导航栏模式属于图形化布局预览，继续保留独立卡片间距，不改为连接按钮；开关和输入框不受影响。
- 当前项目没有共享 `FaButtonGroup`，连接样式仅在 `AppSetting` 内实现，不新增共享组件或 API。

## 交互与数据流

现有流程保持不变：

1. 用户点击布局中的应用配置按钮。
2. 事件总线触发 `global-app-setting-toggle`。
3. `AppSetting` 切换本地 `isShow`，由 `FaModal` 根据 `v-model` 打开或关闭。
4. 表单控件继续直接读写 `settingsStore.settings`，修改后立即预览。
5. 用户点击“复制配置”时，继续复制默认配置与当前配置的差异。

布局调整不新增错误处理分支。弹窗关闭、遮罩点击、Escape 键和内部滚动继续由 `FaModal` 提供。

## 兼容性与风险

- `FaModal` 内置滚动区域，长配置内容不会撑出视口。
- 移动模式强制单栏，避免窄屏横向溢出。
- `FaPageMain` 使用现有语义主题色，明暗主题无需硬编码颜色。
- footer 独立于滚动内容，提示与复制按钮不会被长配置内容挤到滚动区域中。
- CSS 多栏布局按 DOM 顺序流动，卡片使用 `break-inside-avoid` 保证模块完整。
- 配置状态位于 store 中，重新分组不会改变数据生命周期。
- 后续若实施 Motion/Masonry 方案，必须重新验证七个卡片的顺序、移动端单列和所有配置绑定。

## 最终实施结论

- 实现只修改 `apps/admin/src/layouts/components/AppSetting/index.vue`，没有调整共享 `FaModal`、`FaPageMain` 或 `FaButton` API。
- 七个一级模块使用同一组本地 `FaPageMain` 覆盖；外层保留唯一连续轮廓，正文只绘制圆角上边界，避免标题和正文出现双边框。
- 标题最终使用 `14px/16px` 字体行高、`10px` 纵向内边距和语义化 `secondary` 背景。
- 四组互斥选项使用本地连接式小按钮，不新增共享 ButtonGroup。
- footer 保留临时配置提示和全宽复制按钮，复制逻辑、事件总线和 Pinia 绑定未改变。
- 自动验证包括 Prettier、ESLint、Stylelint、Admin typecheck、production build 和 `git diff --check`，均通过。
- 最终实现仍保留缩放类和 CSS 多栏布局；[Motion/Masonry 设计](./2026-08-07-admin-app-setting-motion-horizontal-masonry-design.md)明确属于未实施后续工作。
