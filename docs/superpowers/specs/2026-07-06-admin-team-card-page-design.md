# 后台球队信息卡片页设计

## 背景

当前后台“球队信息”页面位于 `apps/admin/src/views/sports/football/team`，使用 `EsSearch + EsTable + EsListToolbar` 呈现标准 CRUD 表格。足球业务已经明确只维护三支固定球队：皇家高歌、高歌国际、高歌联；比赛轮次页面也依赖“球队数量恰好为 3”的前置条件。

本设计将“球队信息”从“管理任意球队记录”调整为“维护三支固定球队档案”。页面不再强调列表、分页、批量选择、新增和删除，而是用三张球队档案卡展示每支球队的特点、基础资料和编辑入口。

## 目标

- 固定展示三支球队：皇家高歌、高歌国际、高歌联。
- 使用非表格 UI，让每支球队的视觉特点和资料状态更容易识别。
- 保留球队资料修改能力，继续复用现有编辑弹窗和表单提交链路。
- 移除新增、删除、批量选择、分页等不符合固定三队模型的页面行为。
- 保持 `apps/admin` 现有技术栈和样式约定：Vue、Element Plus、UnoCSS、现有权限与 API 模式。

## 非目标

- 不调整数据库结构。
- 不扩展球队字段。
- 不重做后端 `football/teams` 接口。
- 不引入新的 UI 组件库或跨应用共享组件。
- 不把球员数、资产、积分等跨模块统计并入本次页面；这些可以作为后续看板化增强。

## 页面结构

页面仍使用 `FaPageMain` 作为后台页面容器，但内部改为固定档案页：

1. 页头区域
   - 标题：“球队信息”。
   - 辅助说明：“固定维护皇家高歌、高歌国际、高歌联三支球队基础资料”。
   - 右侧保留“刷新”轻量操作，用于重新拉取球队资料。

2. 状态提示区域
   - 当接口返回不是 3 支球队，显示 `ElAlert`，说明当前球队配置异常。
   - 异常提示不阻断已有球队编辑，但提醒管理员需要修复数据。

3. 球队卡片区域
   - 桌面端三列并排。
   - 中等宽度两列。
   - 窄屏单列。
   - 每张卡对应一个固定球队槽位，而不是直接遍历接口返回顺序。

## 球队卡片设计

每张卡片包含以下内容：

- 头部
  - 球队头像；没有头像时使用球队名称首字占位。
  - 球队名称。
  - 固定标识：`real`、`inter`、`united`。
  - 资料状态标签：已配置、资料不完整、未创建。

- 特色区
  - 每支球队使用稳定视觉主题：
    - 皇家高歌：琥珀/金色，表达皇家感和冠军感。
    - 高歌国际：蓝色，表达国际化和稳定。
    - 高歌联：红色，表达凝聚和进攻性。
  - 卡片使用克制的顶部色条、浅色背景块或边框强调，不使用强烈大面积渐变，避免破坏后台管理页的工作感。

- 信息区
  - Slogan。
  - 赞助商名称。
  - 排序值。
  - 创建时间。
  - 更新时间。
  - 资料完整度：头像、Slogan、赞助商名称是否已填写。

- 操作区
  - 只保留“编辑”按钮。
  - 按钮受 `football.team.update` 权限控制。
  - 不提供删除按钮。
  - 不提供批量操作。
  - 不提供普通新增按钮。

## 固定三队数据模型

前端定义固定球队槽位：

```ts
;[
  { code: 'real', name: '皇家高歌' },
  { code: 'inter', name: '高歌国际' },
  { code: 'united', name: '高歌联' },
]
```

页面加载时请求：

```text
GET /football/teams?page=1&pageSize=100
```

然后按固定槽位合并接口数据：

- 优先按 `code` 匹配。
- 若个别历史数据缺少或异常，可按固定名称兜底匹配。
- 卡片渲染顺序始终为皇家高歌、高歌国际、高歌联。
- 接口返回额外球队时显示配置异常提示，但页面只展示三支固定球队。
- 某个固定槽位缺失时展示“未创建资料”占位卡。

## 编辑交互

编辑继续复用现有 `TeamFormDialog`、`TeamForm`、`useCrudDialog` 和 `teamsApi.update`。

规则：

- 点击卡片上的“编辑”打开编辑弹窗。
- 弹窗标题使用“编辑球队资料”。
- 表单字段沿用现有字段：球队名称、排序、球队头像、Slogan、赞助商名称。
- 球队名称仍限定为固定三队选项，避免提交非法名称。
- 由于本页不再提供新增入口，缺失球队只提示配置异常，不在第一版中提供“补全创建”动作。
- 提交成功后关闭弹窗并重新拉取球队列表。

## 权限

- 进入页面仍沿用现有路由和菜单权限。
- 编辑按钮使用 `TEAM_PERMISSIONS.update`。
- 不再使用 `TEAM_PERMISSIONS.create` 和 `TEAM_PERMISSIONS.delete` 渲染页面按钮。
- 可以保留权限常量定义，避免影响其他模块或后续恢复能力。

## 组件拆分

保留现有模块目录结构：

```text
apps/admin/src/views/sports/football/team/
  index.vue
  auth.ts
  components/
    TeamForm.vue
    TeamFormDialog.vue
    TeamProfileCard.vue
  model/
    defaults.ts
    mapper.ts
    types.ts
  schemas/
    form.ts
```

新增 `TeamProfileCard.vue` 承载单张球队卡片，`index.vue` 保持页面装配层职责：

- 请求球队列表。
- 合并固定三队槽位和接口数据。
- 处理刷新、编辑、提交。
- 渲染异常提示和三张卡片。

表格列配置 `schemas/table.ts` 本次保留但不再由页面引用，避免本次改动顺手删除旧文件。

## 错误与空状态

- 加载中：展示三张骨架卡。
- 接口失败：展示错误提示和重试按钮。
- 固定球队缺失：对应卡片展示“未创建资料”，信息区展示占位文案。
- 返回数量不是 3：展示配置异常提示。
- 头像加载失败：回退到首字占位。
- 编辑提交失败：沿用现有接口错误反馈，不关闭弹窗。

## 样式原则

- 使用 UnoCSS 工具类表达布局、间距、边框、圆角、文字和状态色。
- 卡片圆角保持克制，使用 8px 左右。
- 颜色作为识别辅助，不只依赖颜色传达状态；状态仍需文字标签。
- 卡片不嵌套卡片。
- 按钮和可点击区域提供明确 hover/focus 状态。
- 桌面和移动端都避免文字溢出，Slogan 和赞助商名称允许换行。

## 验证计划

实现后至少执行：

- `pnpm --filter @gaoge/app-admin typecheck`
- `pnpm --filter @gaoge/app-admin lint`

手动 smoke test：

- 打开后台球队信息页面，确认三张卡按固定顺序展示。
- 刷新页面，确认加载和错误态无布局异常。
- 编辑任意球队资料，提交成功后卡片内容更新。
- 使用没有更新权限的账号时，确认编辑按钮不可见或不可用。
- 模拟接口少于或多于三支球队时，确认配置异常提示出现。

## 决策记录

- 采用“三队档案卡”方案，而不是左侧切换详情或运营看板式总览。
- 页面作为 `admin-crud.md` 的例外处理：它仍维护实体资料，但业务上不是开放式列表 CRUD。
- 本次只调整后台球队信息页面的展示和维护方式，不修改后端约束。
