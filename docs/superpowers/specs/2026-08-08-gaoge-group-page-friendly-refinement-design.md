# 高歌集团页面友好化调整设计

## 背景

`apps/brand` 的 `/group` 页面已经具备集团首屏、事业部布局、高歌体育、联赛董事会，以及仍在工作区中的企业服务能力和集团协同交付模块。本次在现有视觉基础上收敛页面结构与对外语言，使访问者更容易理解各板块，也减少偏正式、偏商业说明式的表达。

当前工作区存在尚未提交且与集团页重叠的修改。本次实施必须以这些内容为在途成果，只做增量调整，不回退、不覆盖无关改动，也不删除用户未明确要求删除的文件。

## 目标

- 扩大集团页顶部导航的视觉宽度，并统一首页与集团页的 Logo 表达。
- 让集团页事业部介绍与首页能力弹窗的品牌方向和品牌主张完全一致。
- 从公开页面移除“企业服务能力”与“集团协同交付”模块。
- 清理公开页面中的“非营利”“商业”等分类式措辞，改用围绕热爱、伙伴、连接、创造和共同体验的语言。
- 在联赛董事会前展示一版简单的集团管理层。
- 明确页面展示的是本届联赛董事会成员，成员会随届次调整。
- 用集团愿景替代协同交付说明。

## 不在范围内

- 不调整 `/digital`、`/content` 或体育站点的页面结构。
- 不修改首页能力弹窗已经确认的四条品牌主张。
- 不新增管理人员履历、真实头像、联系方式或详情弹窗。
- 不新增 API、CMS、后台配置、依赖或跨应用共享抽象。
- 不改变联赛董事会当前 20 人的昵称、顺序和席位数量。
- 不删除当前工作区中已经存在但不再由页面渲染的组件文件。

## 页面结构

调整后的 `/group` 页面按以下顺序展示：

1. 顶部品牌导航
2. 集团首屏与四个事业部
3. 高歌体育
4. 集团管理层
5. 联赛董事会
6. 集团愿景
7. 页脚

“企业服务能力”不再渲染。“集团协同交付”不再渲染，并由“集团愿景”承担页面收束作用。

## 顶部导航与 Logo

- 集团页导航容器的桌面最大宽度从现有 `max-w-7xl`（1280px）增加至 1440px。
- 移动端边距、高度和胶囊形态保持现状，避免引入新的响应式风险。
- 集团页左上角继续使用现有 `BrandMark`，但其内部 `G` 与首页一致，采用 `-30deg` 旋转与相同字号。
- 不改变首页及其他正式品牌页的导航行为。

## 事业部内容

四个事业部统一使用“事业部名称—品牌方向—品牌主张”结构。集团页展示内容必须与首页能力弹窗使用同一组文案：

| 事业部   | 品牌方向 | 品牌主张                                                 |
| -------- | -------- | -------------------------------------------------------- |
| 高歌数字 | 产品矩阵 | 以技术与产品思维，把想法转化为面向未来的数字能力。       |
| 高歌内容 | 内容运营 | 以创意与内容思维，把热爱转化为持续生长的影响力。         |
| 高歌影视 | 影像创作 | 以影像与叙事思维，把想法转化为承载情感与表达的光影作品。 |
| 高歌体育 | 体育生态 | 以运动与连接的力量，把热爱转化为真实发生的共同体验。     |

`GroupIndustry` 不再承载或展示“企业服务”“企业服务 · 自主创作”“非营利”等性质标签。品牌方向取代性质标签，品牌主张取代原有偏业务定义式描述。

## 整体语言口径

公开页面不再使用以下词汇描述集团及体育板块：

- 非营利
- 商业、商业赛事产品、商业收入目标
- 企业服务、独立采购、签约交付、集团统筹

页面语言优先使用“热爱、伙伴、连接、创造、相聚、共同体验、持续生长”等表达。文字应让普通访问者容易理解，不以组织性质、经营模式或交付流程作为主要叙事。

首屏辅助文案改为：

> 让技术、内容、影像与体育从共同的热爱出发，彼此连接，也持续生长。

## 高歌体育

高歌体育模块保留两张可进入体育站点的卡片，但不再解释非营利或商业边界。

- 模块引导语：`因热爱相聚`
- 模块说明：`从一支球队到每周相见的联赛，让踢球、比赛与相聚成为可以一直延续的共同体验。`
- 高歌 FC：`一群因足球相聚的伙伴，一起训练、比赛，也一起享受每一次上场。`
- 高歌超级联赛：`为球友们持续组织的联赛，让熟悉的人和新的伙伴都能在球场相见。`

卡片目标地址、打开新窗口方式和无障碍名称保持不变。

## 集团管理层

在高歌体育之后、联赛董事会之前增加“集团管理层”模块。第一版只展示三张紧凑人物卡片：

| 昵称   | 职务                   |
| ------ | ---------------------- |
| 劳塔罗 | 集团主席               |
| 齐达内 | 高歌 FC CEO            |
| 劳塔罗 | 高歌超级联赛运营负责人 |

“高歌超级联赛运营负责人”作为优化后的正式职务名称：它比“管理运营人”更自然，同时明确职责范围但不过度拔高职级。

模块说明使用：

> 有人负责方向，也有人把每一次训练、比赛和联赛认真落到日常。

人物继续使用现有默认头像，不虚构照片或个人资料。布局采用三列桌面网格，并在小屏幕自然切换为单列或现有紧凑响应式结构。

## 联赛董事会

- 保留“联赛董事会”作为主标题。
- 增加“本届董事会成员”作为辅助标识。
- 说明文案使用：`以下为本届联赛董事会成员。董事会按联赛届次组成，成员将结合每届联赛的实际情况进行调整。`
- 保留现有 20 名成员、席位编号、默认头像和恰好 20 人的运行时约束。

“本届”比“当期”更符合联赛组织场景，也能清晰表达成员名单并非永久固定。

## 集团愿景

页面末段新增“集团愿景”模块，用来替代“集团协同交付”。该模块不解释采购或协作模式，以一句核心愿景和三条轻量价值表达收束页面：

- 核心愿景：`让每一份热爱，都有生长成事业的可能。`
- 因热爱出发：`从真正喜欢的事情开始，保持好奇，也保持行动。`
- 让想法发生：`用技术、内容、影像与体育，把想法带进真实生活。`
- 与伙伴同行：`珍惜每一次相遇，在共同创造中走得更远。`

视觉沿用集团页的暗色、银灰和鼠尾草绿体系，不引入新的主题色。模块使用简洁的标题、主张和三张文本卡片，不增加复杂交互或动画。

## 数据与组件边界

- `data.ts` 继续作为集团页静态内容的唯一数据入口。
- `GroupIndustry` 改为品牌方向与品牌主张字段；移除页面不再需要的性质字段。
- `groupLeaders` 收敛为本次确认的三名管理层记录。
- 新增集团愿景静态数据类型或组件内常量时，以页面私有、最小实现为准，不抽取到共享包。
- `GroupPage` 负责模块编排，移除 `BusinessCapabilities` 和 `DeliveryModel` 的渲染，增加 `LeadershipStructure` 和集团愿景组件。
- 已有 `BusinessCapabilities.tsx` 与 `DeliveryModel.tsx` 不因本次任务直接删除，避免破坏用户在途文件；它们不再出现在公开页面中。

## 可访问性与响应式

- 新增模块使用语义化 `section`、标题关联和列表结构。
- 人物默认头像继续作为装饰元素隐藏于辅助技术，昵称与职务提供完整信息。
- 桌面导航扩大宽度后仍使用居中容器；移动端不产生水平溢出。
- 三人管理层和三项愿景在窄屏下改为单列。
- 不新增仅依赖颜色传递的信息。

## 验证

自动化测试应覆盖：

- 集团页 Logo 与首页使用相同的旋转和字号。
- 集团页导航使用新的 1440px 最大宽度。
- 四个事业部展示与首页能力弹窗一致的品牌方向和品牌主张。
- 页面不存在“企业服务能力”和“集团协同交付”标题。
- 页面不存在“非营利”“商业”等已移除口径。
- 高歌体育展示新的友好文案，并保留两个外链。
- 集团管理层恰好展示三人及确认的昵称、职务。
- 联赛董事会恰好展示 20 人，并出现“本届董事会成员”和届次调整说明。
- 集团愿景及三条价值表达均可见。

实现完成后运行：

```bash
pnpm --filter @gaoge/app-brand test
pnpm --filter @gaoge/app-brand typecheck
pnpm --filter @gaoge/app-brand build
pnpm lint:style
```

并在桌面与移动端分别检查 `/group` 的导航宽度、内容层级、卡片换行和横向溢出。
